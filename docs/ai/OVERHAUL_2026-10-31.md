# 10-31 개편 — 로컬 MCP를 실제로 잡고, 엔드포인트와 콘솔을 쓸 수 있게

소유자 10-31 지적을 근거로 한 개편 설계. 결정 번호는 D-301~D-305.

## 0. 지적과 확인한 사실

| 지적 | 확인(10-31, :8000 콘솔·DB·코드) |
| --- | --- |
| 로컬 MCP가 중앙에 안 남는다 | pj3에서 Ghidra MCP로 Codex가 4개 도구를 호출했지만 중앙에는 인벤토리 `shadow` 행 3개뿐. 호출 기록·경보·감사 체인 없음. 경보는 게이트웨이 호출 판정(`decisions`)에서만 생긴다. |

| 알림창이 없다 | `ops_alerts`는 쌓이지만 콘솔 어디에도 보이지 않는다(`/api/ops/status` JSON에만 있음). |

## 1. 원칙

1. **로컬 MCP 호출도 게이트웨이 원장에 남는다.** 승인 여부와 관계없이 하네스가 부른 로컬 stdio MCP의 `tools/call`은 엔드포인트 중계가 기록해 중앙으로 보낸다.
2. **커넥터는 기본 승인, 발견되면 목록, 문제면 중앙 차단.** 하네스 계정에 붙는 공식 커넥터(claude.ai 커넥터·ChatGPT 앱)는 검증된 것으로 본다.
3. **모델 기본 기능은 MCP가 아니다.** 이미지 생성·메모리·웹 검색 같은 기능은 「하네스 설정」에서 켜고 끄며 MCP·커넥터 목록에 섞지 않는다.
4. **엔드포인트 사용자는 자기 PC에서 보고 고칠 수 있다.** CLI와 로컬 웹 화면이 같은 기능을 갖고, 중앙이 그 범위를 정한다.
5. **콘솔은 흐름이 보여야 한다.** 첫 화면은 그래프와 조치 목록, 숫자는 작게. 모든 숫자는 해당 목록으로, 목록 행은 상세로, 상세는 조치 버튼으로 이어진다.

## 2. D-301 로컬 MCP 통제 구멍과 모든 MCP 호출의 중앙 기록

- **통제 구멍(수정):** Codex는 `requirements.toml`에 `[mcp_servers]` 표가 **없으면 제한하지 않고, 비어 있으면 전부 끈다**(learn.chatgpt.com managed configuration). 승인 서버가 0개인 PC는 표가 빠져 pj3의 Codex가 미등록 Ghidra MCP를 그대로 썼다. 세 렌더러(엔드포인트 정책·실기기 키트·실습 워크스테이션)가 항상 표를 둔다. pj3 재시험: `ghidra … disabled: requirements`, 모델은 도구를 받지 못함.
- **기록 방식(조사 반영 변경):** stdio 중계 대신 **하네스 관리형 훅**. Obot Sentry·Runlayer·Endor·Mintive의 공통 방식이다. Claude Code `managed-settings.json`과 Codex `requirements.toml`에 `PostToolUse` 훅(`mcp__*`)을 넣고 사용자·프로젝트 훅은 계속 막는다(`allowManagedHooksOnly`·`allow_managed_hooks_only`).
- 훅은 키트의 `agent.py hook <하네스>`다. 직원 홈 `.mcpgw/tool-events.jsonl`에 서버·도구 이름, 인자 크기·SHA-256, 결과 크기, 실패 여부만 한 줄 남긴다(내용은 남기지 않음). 서비스(장치 키 보유)가 1분마다 `/api/endpoint/tool-events`로 보낸다. 링크·정션·장치 파일은 읽지 않는다.
- 중앙은 `endpoint_tool_events`(추가만)에 경로를 붙인다: 레지스트리 서버 = 게이트웨이, `claude_ai_*`·`codex_apps` = 커넥터, 그 밖 = 로컬. 로컬 경로 서버의 첫 호출과 엔드포인트가 보고한 미등록 설정·확인된 수신기는 `unapproved-endpoint-mcp` 경보(SIEM 큐 포함).
- 셸 차이: Windows Codex는 훅을 PowerShell로 실행해 `&` 호출 연산자가 필요하고, Claude Code는 실행 파일·`args`를 나눠 둔다(Git Bash·PowerShell 어느 쪽이든).
- 검증(pj3, 10-31): Codex ChatGPT 앱 호출 → `hook: PostToolUse Completed` → 콘솔 「호출·감사 기록 > 엔드포인트 호출」에 `codex_apps / pets__list_pets`, 경로 커넥터.
- 한계: 기록 파일은 직원이 지울 수 있다(삭제 전 1분 안의 전송분만 확실). Claude Code 훅의 Windows 실기기 실행은 아직 미확인. 사용자 훅 차단 모드(PreToolUse 거부)는 미구현.

## 3. D-302 엔드포인트 사용자 기능 — CLI와 로컬 웹 화면 동등

| 기능 | CLI | 로컬 웹(`mint ui`) | 중앙 통제 |
| --- | --- | --- | --- |
| 상태 | `mint` / `mint --check` | 첫 화면 | — |
| 내 MCP(승인·미등록·커넥터) | `mint servers` | 「MCP」 | 목록·차단 |
| 호출 기록 | `mint logs [--server] [--since]` | 「호출 기록」 | 보존 기간 |
| 도입 신청 | `mint request <이름>` | 행의 「신청」 | 승인 |
| 자가 점검·복구 | `mint repair` | 「점검·복구」 | 허용 여부 |
| 하네스 로그인 | `mint login claude|codex` | 「로그인」 | — |

- `mint ui`는 `127.0.0.1`의 임시 포트에 표준 라이브러리 HTTP 서버를 띄우고 일회용 토큰이 붙은 주소를 기본 브라우저로 연다. 창을 닫으면 끝난다.
- CLI와 웹은 한 명령 표(`commands`)를 같이 쓴다. 새 기능은 표에 한 번 넣으면 둘 다 생긴다.

## 4. D-303 커넥터와 하네스 기능 분리

- **커넥터**(claude.ai 커넥터·ChatGPT 앱·하네스 계정에 붙는 원격 MCP): 기본 승인. 누군가 켜면 엔드포인트 보고로 목록에 생긴다. 상태 표시는 `사용 중`(기본)·`차단`. `관찰만` 경고색을 쓰지 않는다. 중앙 차단은 D-298 경로 그대로.
- **하네스 기능**(웹 가져오기·웹 검색·브라우저·컴퓨터 조작·이미지 생성·메모리·플러그인): 「정책 > 하네스 설정」 표. 하네스별 켬/끔 스위치, 기본 켬. MCP 목록에서 뺀다.
- 미등록 MCP는 **이름+하네스로 한 행**, 엔드포인트 수·최근 관측을 열로.

## 5. D-304 콘솔 정보 구조·흐름

- 메뉴: 대시보드 · 처리할 일(승인·도입·경보) · MCP(등록 서버·커넥터·미등록) · 사용자·엔드포인트 · 기록(호출·감사·경보) · 정책(정책·하네스 설정) · 종료·폐기.
- 상단 바에 **경보 종** — 읽지 않은 경보 수, 누르면 최근 경보 목록, 행은 대상 화면으로.
- 대시보드 첫 화면: 작은 숫자 줄(한 줄) → 24시간 판정 추이 그래프 + 서버별 호출 막대 → 「처리할 일」 목록 → 최근 경보·차단(한 줄 한 건).
- 종료·폐기: 행·상세·확인 창 제목은 **서버 이름**, 목적은 보조 줄. 등급 T1~T3는 `완전 종료`·`부분 종료`·`종료 불가` 같은 말로.
