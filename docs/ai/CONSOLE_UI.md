# Console — 운영 화면

소스: `full_stack_lab/gateway/app/agent_static/`. 결정 기록은 [D-66](DECISIONS.md).

로컬 MCP 승인 미리보기·호출의 종료 오류는 D-200에 따라 한국어 사유·확인된 종료 코드·비밀을 숨긴 표준 오류를
기존 오류 표시 경로로 전달한다. 콘솔의 `toast`는 `textContent`로 표시하며 실행기 진단을 HTML로 해석하지 않는다.
표준 오류는 최대 5줄·300자, 전체 진단은 500자다. 원시 예외와 검사하지 않은 장치 오류는 일반 오류 경계를 유지한다.

## 화면 원칙 (소유자 규칙, 2026-10-03)

Console은 바로 판매할 수 있는 제품 화면이다. 아래를 어기는 변경은 하지 않는다.

1. **라벨과 값만** 둔다. 페이지 설명 문단, 도움말, 브레드크럼, 부제, "~합니다"식 안내문, 주석 같은 칩
   ("하네스 이름은 자기 신고" 등)을 넣지 않는다. 확인 대화상자의 결과 한 줄("이후 호출은 차단됩니다")은 허용한다.
2. **개발 흔적 금지**: D-번호, PAC-15·팀원·실습·v3/v4·WIP, 빌드 SHA·버전 표, 시험 데이터, 참고한 제품 이름,
   영어 enum 원문(approved, Registry, disabled…)을 화면에 내지 않는다. 브라우저로 내려가는 HTML·CSS·JS 주석도 같다.
3. **용어**: 게이트웨이 · 엔드포인트 · 벤더(한글). 장치도 엔드포인트다. `단말`·`커널`·Gateway/Endpoint 혼용 금지.
   엔드포인트가 막은 것은 "엔드포인트에서 차단", MCP 서버 URL은 "MCP 주소".
4. **약어 표식 금지**(GW/EP/VD, AA/NF/CF/UA 등). 상태값은 모두 한국어로 번역하고 값이 없으면 `—`.
5. **조작할 수 없는 기능은 화면에 두지 않는다**(예외 등록부, A.I.G mcp-scan, 구성요소·배포 해시 표, 실습 복원 버튼).
6. 같은 개념은 어디서나 같은 표기: 등급은 `T1 종료`/`T2 부분 종료`/`T3 판단 불가`, 예상치는 `예상 T1 종료` 형식.
7. 문장은 "~합니다/~하세요"체. "~요"체를 쓰지 않는다.
8. 같은 수치를 두 번 보이지 않는다. 탭 건수와 같은 값의 KPI 카드, KPI·표와 같은 값의 분포 차트, 다른 화면과 같은 표·차트를 두지 않는다.
   표 안의 값이나 필터로 알 수 있는 분포는 차트로 다시 그리지 않는다. 해시·추적 ID는 상세의 접힌 영역에 둔다.

## 구성

내 PC 연결은 운영체제 버튼으로 선택만 하고 선택한 운영체제의 절차와 「설치 파일 받기」를 아래에 둔다(D-230). 사용자·엔드포인트의 「삭제된 사용자」 탭에서 관리자가 계정을 복구한다.

내 PC 연결의 Windows 다운로드는 자체 추출 `.cmd` 파일을 받으며, 기존 인증 API의 `packaging=oneclick`을 사용한다(D-197).
기본 ZIP 응답은 조직 IT의 승인 배포용으로 유지한다. 설치 결과에 관리 계정·활성화 대기·모델 로그인 명령을 표시한다.

도입 신청의 관리자 검토는 한 대화상자에서 제안값·검사·도구 계약을 읽고 승인/거부, 도구 선택 축소, 기본 90일 기한 선택으로 처리한다(D-184~187). 공급자 보증·위치·영향평가 제안값은 추가 정보 영역에 둔다. 활성 관할 팩의 위치 항목과 치명적 발견 수용 사유만 조건부로 필수다. 높은 등급의 두 번째 관리자는 첫 승인과 같은 범위를 읽고 승인한다. 자동 제안은 실행·공급자 검증 완료 표시가 아니다.

상단 바: 메뉴 접기 · 로고(하나) · 호출 검색 · 사용자 · 언어 · 테마 · 로그아웃. 사이드바는 메뉴만 둔다.

| 종료·폐기 | 이용 관계(표, 행을 누르면 상세) · 케이스 |

관리자 메뉴는 운영(대시보드 / 호출과 감사 기록), 접근 통제(AI 연결 관리 / 사용자 관리 / 엔드포인트 관리 / 정책), 도입 및 종료(도입 신청 / 종료와 폐기), 내 계정(이용 동의 / 내 연결)의 10개다(D-303).
직원과 협력사는 호출 기록, 도입 신청, 이용 동의, 내 연결의 4개를 유지한다. 감사와 실행 확인, 승인 처리 이력, 공급망 탭은 `viewer.admin`일 때만 구성한다. 이용 동의는 역할과 관계없이 로그인한 본인의 요청만 처리한다.
대시보드 배지는 호출 승인 건수, 이용 동의 배지는 본인이 확인할 서버 수, AI 연결 관리 배지는 커넥터 검토 건수다. 호출 승인 요청은 호출 승인 탭에서만 조회하고 처리한다. 요약에는 승인 요청 미리보기를 표시하지 않는다. 가입 승인과 엔드포인트 활성화 및 도입 조치는 해당 관리 페이지로 연결한다.
통제 적용 현황은 대시보드의 별도 탭으로 두지 않는다. 연결 유형별 통제 현황 그래프는 AI 연결 관리의 연결 목록 상단에 두고 연결 항목 수를 집계한다. 그래프 선택은 해당 유형과 상태의 연결 목록으로 이동한다. 상단의 통제 점검 필요 연결 건수는 유지하며 최대 8건 점검 미리보기와 영향 범위 추정은 제거했다. 기존 `#/overview?t=planes`는 검색과 상태 필터를 보존해 `#/servers?t=items`로 연결한다.
호출 분석은 호출 및 감사 기록의 분석 탭으로 모은다. 기존 호출 추이와 응답 처리 및 서버별, 사용자별 판정에 정책별 차단과 경보, 엔드포인트별 호출 및 하네스별 호출 판정을 추가한다. 목록과 분석은 기간, 호출 유형, 판정, 서버, 사용자, 엔드포인트, 정책 및 검색 조건을 공유한다. 기본 범위는 최근 24시간의 도구 호출이며 전체 기간과 연결 이벤트도 선택할 수 있다. 조건 변경은 주소에 반영하고 이전 필터의 늦은 분석 응답은 적용하지 않는다. 기존 `#/overview?t=traffic`은 분석 탭으로 이동하고 기간 미지정 시 최근 24시간의 도구 호출을 선택한다.
새 집계는 호출 원장의 동일 조회 조건을 사용하고 직원과 협력사는 기존 본인 범위를 유지한다. 관리자 화면에 추가 통계를 표시하며 직원 화면의 분석 구성은 기존 범위를 유지한다. 엔드포인트는 현재 등록 목록과 조인하지 않고 기록의 식별자를 사용하며, 미확인과 등록 해제된 기기의 과거 호출도 집계한다. 엔드포인트 표에는 호출 수와 판정 분포 및 마지막 호출만 표시한다. 정책 통계는 차단과 경보 판정만 집계하며 다른 차트는 선택된 전체 판정을 집계한다. 차원별 상위 12개 이후는 기타로 묶어 합계를 보존한다. 하네스와 서버를 잇는 도식은 실행 성공이나 개별 네트워크 경로 검증이 아닌 호출 판정 집계다.
성능 탭의 내부 키는 latency를 유지한다. 호출 처리 성능은 최근 24시간의 전체 처리와 게이트웨이 처리 및 MCP 통신과 처리의 중앙값, 95백분위 및 측정 호출 수를 표시한다. 게이트웨이 내부 측정이며 직원 PC나 모델 응답 전체 시간은 아니다. MCP 통신과 처리는 도구 전송 구간이 기록된 호출의 연결, 계약 재확인, 실행 요청과 세션 종료 시간 합계다. 구간별 표는 각각의 측정 호출 수와 중앙값 및 95백분위를 표시한다. 서로 다른 구간의 백분위 값을 합산하지 않는다.
성능 API의 집계는 하나의 시작과 종료 시각을 공유하고 서버 표는 95백분위 높은 순서로 최대 12개를 표시한다. MCP 처리 오류는 허용 후 MCP 처리 미완료 정책으로 기록된 건수이며 모든 실패나 실행 안 됨을 뜻하지 않는다. 서버에서 호출 기록으로 이동할 때 측정 기간과 도구 호출 유형을 전달한다. 조회 실패와 측정 없음은 구분하고 새로고침으로 다시 조회한다.
엔드포인트 → 게이트웨이 통신은 기기별 최근 TCP 연결 시간의 중앙값과 연결 시간 95백분위, 연속 성공 측정 간 차이의 평균인 변동, 점검 실패율, 점검 횟수와 최근 측정 시각 및 측정 상태를 표시한다. 기기 이름을 먼저 표시하고 식별자를 보조로 둔다. 제목 옆 조회 시각은 API 조회 시점이며 행의 최근 측정 시각과 구분한다. 점검 실패율은 TCP 연결과 상태 확인 요청을 포함하며 패킷 손실률이 아니다. 점검 횟수에도 두 종류가 포함된다는 호버 설명을 제공한다. 조회 시점 3분 이내의 측정은 최근, 보고가 만료되면 시간 값을 숨기고 오래됨, 보고가 없으면 미측정, 최근 보고이나 연결 값이 없으면 측정 실패로 구분한다. 최근이라는 표시를 통신 정상 판정으로 해석하지 않는다. 각 측정 묶음의 백분위 값을 다시 집계한 전체 요약은 화면에 표시하지 않는다. API 요약 필드는 호환성을 위해 유지한다. 요약의 내부 TCP 측정은 콘솔 서버에서 게이트웨이로의 연결 시간으로 구체화한다.
호출 승인은 만료 시각이 가까운 요청부터 정렬하고 같은 만료 시각에서는 요청 시각과 ID로 순서를 고정한다. API는 30건 단위 페이지와 전체 대기 건수 및 가장 오래된 요청 시각을 제공한다. 호출 승인 탭은 선택한 페이지의 요청자, 도구와 대상 요약, 만료 시각, 승인 사유, 행위와 데이터 등급 및 요청 시각을 표시한다. 하네스는 상세에서 확인한다.
목록에는 검토 버튼만 두고 상세 화면에서 승인 또는 거부한다. 일반 승인은 실행을 알리는 최종 확인을 거치며 중대 영향 승인은 기존 범위 확인과 증빙 해시를 유지한다. 본인 요청은 승인할 수 없다. 처리 이력에는 실행 버튼을 추가하지 않는다. 요약과 호출 승인 탭에서 15초마다 목록을 갱신하고 상세 검토나 확인창, 목록 내부 키보드 포커스가 있으면 자동 교체를 보류한다. 갱신 실패는 기존 목록과 함께 표시하고, 화면을 이동한 뒤 도착한 응답은 적용하지 않는다. 빈 마지막 페이지는 유효한 마지막 페이지로 이동한다.
대시보드 상단은 확인 및 조치와 오늘 도구 호출 순서다. 오늘 도구 호출에는 전체 호출과 차단된 호출만 표시하며 두 수치를 모든 실행 결과의 완전한 분류로 취급하지 않는다. 확인 및 조치는 실행 여부 확인, 연결 통제 점검, MCP 서버 점검, 종료 처리의 네 항목이며 합계를 만들지 않는다. 상단 값과 기한 초과 보조 수치는 단위 없이 숫자만 표시하고 값이 없으면 대시를 표시한다. 요약 탭은 승인 및 등록, 최근 차단 10건 순서다. 승인 및 등록에는 가입 승인, 엔드포인트 활성화, 도입 조치를 표시한다. 시스템 자원은 성능 탭 하단에서 CPU 부하, 메모리 사용, 콘솔 서버에서 게이트웨이까지의 연결 시간을 표시한다.
실행 확인 필요는 `dispatch.uncertain_count()`의 현재 미해결 전체 건수이며 날짜나 목록 200건 제한을 적용하지 않는다. 통제 점검 필요 연결은 기존 우회 가능 상태의 중복 제거된 연결 목록으로 이동한다. MCP 점검 필요는 연결 오류, 계약 변경, 확인 대기 상태를 세고 동일 조건으로 필터링된 서버 목록으로 이동한다. 종료 조치 필요는 등급과 무관한 미종결 전체 케이스 수이며 기한 초과는 보조 링크로 표시한다. 종료 목록은 DB에서 미종결 또는 기한 초과 조건을 적용한 후 50건씩 페이지를 나눠 조회한다. 종료 판정 규칙은 변경하지 않는다.
기존 `#/audit`은 `#/activity?t=events`, `#/coverage`는 AI 연결 관리의 연결 목록으로 이동한다. coverage의 devices/shadow 탭은 엔드포인트 관리의 동일 탭으로, vendor는 AI 연결 관리의 동일 탭으로 연결한다. 기존 `#/people?t=devices`와 `#/people?t=managed` 및 `#/servers?t=shadow`도 엔드포인트 관리로 이동한다. `#/sbom-impact`는 `#/intake?t=impact`로 이동한다. 기존 `#/approvals`는 대시보드의 호출 승인으로, unsent와 history 탭은 호출 및 감사 기록의 실행 확인과 승인 처리 이력으로, consent 탭은 본인의 이용 동의로 필터를 보존해 이동한다.
탭 데이터는 상위 화면을 읽을 때 함께 구성하며 기존 호출 로그의 실시간 갱신과 도입 신청의 갱신 훅을 유지한다. 도입 신청의 새 신청·공급망 영향 폼은 자동 갱신으로 바꾸지 않는다.
데스크톱은 펼친 메뉴, 900px 이하는 접힌 메뉴로 시작한다.
문서 루트는 `scrollbar-gutter: stable`로 세로 스크롤바 공간을 유지한다. 미지원 브라우저는 `overflow-y: scroll`로 같은 폭을 유지한다.
성능 탭은 호출 처리 성능, MCP 서버별 통신 및 처리, 구간별 처리 시간, 엔드포인트 → 게이트웨이 통신, 시스템 자원 순서로 표시한다.
엔드포인트 통신 표는 엔드포인트와 연결 시간, 점검, 측정 그룹으로 구성한다. 연결 시간 아래 중앙값, P95, 변동을, 점검 아래 실패율과 횟수를, 측정 아래 최근 시각과 상태를 둔다. 각 호버 설명과 표의 열 그룹 관계를 유지한다. 영역의 조회 시각은 측정 시각과 구분해 표시한다.
그룹 시작 지점에만 세로 구분선을 두고 머리글의 두 행부터 데이터 행까지 연결한다. 그룹 경계의 좌우 여백을 넓히며 같은 그룹 내부에는 세로선을 추가하지 않는다. 이 스타일은 엔드포인트 통신 표에만 적용한다.
대시보드 상단 KPI는 두 영역 모두 156px 공통 행 높이를 사용한다. 화면 폭에 따라 열이 바뀌어도 카드 높이를 유지하며 다른 페이지 KPI에는 적용하지 않는다.
대시보드 지표와 집행 모드 및 구성 요소 상태, 가입 승인과 활성화 및 도입 건수, 최근 차단 목록은 30초마다 해당 영역만 갱신한다. 숨겨진 문서나 열린 상세 및 확인창, 갱신 대상 내부의 키보드 포커스가 있으면 보류한다. 이전 화면의 늦은 응답은 적용하지 않고 조회 실패 시 이전 값과 갱신 실패 상태를 유지한다. 최근 차단 미리보기는 최근 24시간의 도구 호출 중 차단 10건이며 이동 링크에 같은 시작과 종료 시각 및 호출 유형을 전달한다.
가입 요청 API는 상태 필터와 100건 단위 페이지, 필터에 맞는 전체 건수와 별도의 전체 대기 건수를 제공한다. 대시보드 가입 승인에는 전체 대기 건수를 표시하고 대기 필터 목록으로 이동한다. 사용자 관리에서 상태별 조회와 페이지 이동을 제공한다. 실행 확인 API는 기존 미해결 조건의 전체 건수와 200건 단위 페이지를 제공한다. 처리 후 요청 페이지가 비면 서버가 남은 마지막 페이지로 보정한다. 기존 인증과 승인 및 실행 확인 처리 규칙은 유지한다.
호출 상세는 요청 → 게이트웨이 → 엔드포인트 → 도구 실행 → 응답 다섯 단계로 보여 준다.
호출 목록·호출 상세의 실행 결과·감사 목록·감사 상세에는 연결·정책 판정·도구 업무·독립 효과를 각각 한국어 라벨과 값 칩으로 표시한다(D-136).
정책 허용과 MCP 응답 수신은 독립 효과를 증명하지 않는다. 관리자 실행 확인이 없으면 전송한 호출의 독립 효과는 미확인이다.
종료 케이스의 절차 막대는 앞 단계가 끝나야 다음 단계가 완료로 표시되고, 종결된 케이스는 모두 완료로 표시한다.

## 언어와 글자 크기 (D-211)

조직 보안 정책은 정책 원본과 구현 분류에서 재생성한 읽기 전용 카탈로그를 조회한다(D-302).
정책 대상과 적용 단계, 구현 방식과 코드 존재를 표시하며 조직 적용 확인은 별도로 미확인으로 둔다.
정책 상세에서 본문, 판단 요건, 시험 정의와 현재 관리대장에 존재하는 보안 통제 규칙 검토 후보를 확인한다.
후보는 검토된 POL 매핑이 아니며 판정 코드 존재와 시험 정의를 실제 집행 및 시험 통과로 표시하지 않는다.
카탈로그는 `python policy/tools/build_console_catalog.py`로 생성하고 `--check`로 원본 일치를 검사한다.

정책 로드 상태는 원본 조회와 OPA 룰셋 일치 여부 및 OPA 정책 데이터 일치 여부를 각각 표시한다(D-301). 조회 기준 시각은 서버가 요청 처리를 시작한 시각이다.
원본 조회 결과는 정책 로드 상태 제목 옆의 공통 배지로 표시한다. 조회 확인은 초록, 조회 실패는 빨강, 미확인은 회색이다. 판정 기록 조회 기간은 제목 옆의 작은 회색 보조 글씨로 표시하며 본문에서 반복하지 않는다.
관리대장의 운영 상태나 해시 일치를 현재 집행 경로 검증으로 표시하지 않는다.
정책 상세는 정의, 집행 근거, 명시적 POL 연결로 나누며, 최근 24시간의 최종 판정 집계와 감사 기록 링크를 제공한다.
원장 조회의 시작과 종료는 API의 확인 시각으로 고정한다. 원본 조회 실패 시 과거 캐시를 현재 정책으로 표시하지 않는다.
POL 연결은 관리대장의 pol_ids만 사용하며 요구사항 번호로 추론하지 않는다. 검토된 연결이 없으면 매핑 미확인이다.
집행 경로 시험은 미수행으로 표시하고 독립 효과 항목은 감사 화면에서 확인한다. 관찰 모드 처리는 차단 유지와 전환 가능으로 구분한다.
호출 원문, 사용자 권한 목록, 독립 효과 상세는 해당 관리 및 감사 화면에서 확인한다.

- 한국어가 원문이고 영어는 `i18n-en.mjs` 사전으로 렌더 뒤에 바꾼다(`i18n.mjs`가 화면·대화상자·토스트·속성을 한 번에 처리하고, 차트 글자는 `charts.mjs`가 같은 사전으로 바꾼다).
  상단 바의 언어 버튼(한국어 / English)은 `localStorage`의 `mcp-console-lang`에 기억하고 페이지를 다시 읽는다. 기본은 한국어, 로그인·가입 화면도 같은 키를 쓴다.
- 새 화면 문구를 추가하면 같은 변경에서 사전에 영어를 더한다. `tests/i18n.test.mjs`가 소스의 모든 한국어 문구를 정적으로 뽑아 사전 누락이 있으면 실패한다.
  사전 키: `{}`는 아무 글자, `{n}`은 한글 없는 글자(숫자·시각·ID), 값의 `{1}`은 캡처, `{1?단수:복수}`는 복수형. `[button]`·`[tab]`·`[nav]`·`[heading]`·`[label]`·`[column]` 접두는
  같은 한국어가 상태(승인)와 동작(승인)으로 달라질 때만 쓴다. 영어는 문장형 소문자(sentence case)로 쓰고 개수는 단수·복수를 가린다.
- 서버가 돌려주는 한국어(오류 문장, 정책 이름·조건, 판정 사유)는 번역하지 않고 그대로 보인다. 서버가 보내는 짧은 표시 값(호출 결과 축, 역할, 행위)은 사전에 있다.
- 시각은 영어에서 24시간제 `Oct 23 14:05` 형식, 한국어는 기존 `10-23 14:05`.
- 글자 크기는 이전의 90%다(`console.css`·`login.css`의 글자 크기 값과 `charts.mjs`의 차트 글자). `zoom`은 쓰지 않는다. 본문·코드 줄 높이는 줄 간격이 그대로이도록 배수를 올렸다.

## 공통 구현

- 모든 데이터는 `html```로 이스케이프한다. 인라인 스크립트·`style=` 없음(CSP same-origin).
- 차트는 ECharts. 숨긴 탭·닫힌 펼침 영역에서는 그리지 않는다.
- 상세는 native `dialog`. Enter·Space로 행을 열 때 기본 동작을 취소하고, Escape 뒤 원래 행으로 초점을 돌린다.
- 감사 조회의 시작·종료는 `datetime-local`로 받고 UTC ISO로 보낸다.

## 후속 검증

이용 동의의 확인 필요 목록은 서버별로 묶고 현재 표시된 요청 전체에 `모두 허용`·`모두 거부`를 제공한다(D-201).
배지·확인할 서버 수는 서버 개수다. 도구별 목적·등급·입력·외부 목적지와 처리 기록은 유지한다.
클릭 후 새로 생긴 요청은 함께 승인하지 않으며 다른 사람·서버·처리 완료 요청이 섞이면 전체를 거부한다.

감사 화면의 `보안 관제 전달`은 대기·재시도·최초 대기·최근 수신 확인 값만 표시한다. 관리자 API `/api/audit/siem`을 읽으며 SIEM 수신 주소·자격·원문은 내려주지 않는다. 서버가 계약 변경 상태여도 도구별 계약 일치 표시는 최신 제한 범위를 함께 반영한다. 브라우저 렌더링 검수는 이 변경에서 미실행이다.
