# 수동 시험 매뉴얼 — Windows 직원 PC

Windows 10/11 직원 PC에 원클릭 키트를 설치하고 승인된 MCP를 실제 하네스로 써 보며 게이트웨이 판정을 확인하는 절차다.
한 번 끝까지 하는 데 약 30분. 결과는 맨 아래 기록 표에 적는다. Linux는 [MANUAL_TEST_LINUX.md](MANUAL_TEST_LINUX.md).

## 0. 준비

| 항목 | 내용 |
| --- | --- |
| 게이트웨이 | `https://<게이트웨이 주소>/` 에 콘솔이 열리고 로그인할 수 있어야 한다. 주소는 운영 담당에게 받는다 |
| 계정 | 직원 계정 1개(시험 대상), 관리자 계정 1개(동의·승인 확인용, 시험 직원과 다른 사람) |
| PC | Windows 10/11 x64. 지금 로그인한 계정 그대로 설치한다(관리자·표준 모두, 로그아웃 불필요). 설치 때 관리자 권한 확인(UAC) 1회 |
| 하네스 | Claude Code(PowerShell에서 `claude --version`) 또는 Codex CLI(`codex --version`)가 이 계정에 설치·로그인돼 있음 |
| 문서 폴더 | 시험용 파일을 둘 `%USERPROFILE%\mcp-docs` |
| 로컬 MCP | 파일·기억·단계별 사고 같은 **로컬 MCP의 PC 격리 실행은 Linux 키트에서만** 지원한다. Windows에서는 원격 MCP로 시험하고, 로컬 MCP 호출 결과는 「확인 필요」로 기록한다 |

시험 중 콘솔에서 볼 곳: **도구 호출 로그**(판정·정책 ID·처리 시간), **이용 동의**, **MCP 서버**(서버 상세 → 범위), **사용자·엔드포인트 → 엔드포인트**, **내 연결**.
판정은 「허용(Allow)/차단(Block)/경보(Alert)」과 **정책 ID까지** 확인한다.

## 1. 설치

1. 브라우저로 콘솔에 직원 계정으로 로그인 → 왼쪽 아래 **PC 연결 설정** → **Windows**(기본 선택) → **설치 파일 받기**(`mcp-managed-setup-windows.cmd`).
   - 「고급: 격리 계정」은 체크하지 않는다(기본 간편 모드). 격리 계정 시험은 7절.
2. 받은 `.cmd`를 더블클릭 → UAC에서 **예**. 설치 마법사가 단계를 보여 준다(한국어/English 전환 가능).
3. 끝 화면의 **세 칸**을 확인한다.

   | 칸 | 통과 기준 |
   | --- | --- |
   | 모델 응답 | 하네스가 실제로 답함 |
   | 도구 | 승인 서버마다 도구 수가 0보다 큼 |
   | 서버 연결 | 승인 서버 1건 연결 성공 |

   실패하면 사유 아래 「다음:」 한 줄을 따르고, 그 문구를 기록한다.
4. 활성화: 콘솔 **사용자·엔드포인트 → 엔드포인트**에서 이 PC가 「활성」인지 본다(「새 PC 활성화」가 「자동」이면 설치 직후).
5. **PowerShell 창을 새로 연다**(사설 인증서 경로 환경 변수는 새 프로세스부터 적용된다).

기록: `.cmd` 실행~세 칸 표시까지 걸린 시간, 활성화까지 걸린 시간.

## 2. 상태 확인 — 트레이

작업 표시줄 알림 영역의 MINT 아이콘을 연다.

| 메뉴 | 확인 |
| --- | --- |
| 상태 창 | 연결 「연결됨」, 관리 상태 「활성」, 모드 「간편」, 승인 서버 목록, 하네스 판본, 세 칸, 다음 할 일 |
| 연결 확인 | 세 칸을 다시 잰다 |
| 모델 로그인 | Claude·Codex 로그인 창 |
| 다시 연결 | 게이트웨이 점검, 서비스가 멈췄으면 관리자 권한으로 다시 시작 |
| 콘솔 | 콘솔 열기 |

통과: 승인 서버 목록이 콘솔 **MCP 서버**의 사용 가능 서버와 같음. 150초 넘게 보고가 없으면 「연결 끊김」으로 바뀐다.

## 3. 정상 기능 시험

각 항목은 **새 PowerShell**에서 `claude -p "<프롬프트>"`(Codex는 `codex exec "<프롬프트>"`)로 실행한다. 대화형도 된다.
서버 이름은 콘솔 **MCP 서버**의 표시 이름을 쓴다.

### 3.1 첫 사용 동의 → 재호출 (원격 문서 MCP)

1. `claude -p "Microsoft Learn MCP로 'Azure Functions Python v2 HTTP trigger' 문서를 검색해 핵심 3줄로 요약해. 차단되면 차단 코드와 사유를 그대로 적어."`
2. 기대: 처음이면 `P-CONSENT-001` 「이 도구의 데이터 이용에 사용자 동의가 필요합니다」. 콘솔(직원) **이용 동의 → 확인 필요**에서 허용.
3. 같은 문장 다시 → **도구 호출 로그**에 `Allow`·`P-AUTHZ-ALLOW-001`. 처리 시간을 적는다.
4. DeepWiki·Cloudflare Docs·AWS Knowledge·Hugging Face·Grep도 한 번씩.

### 3.2 GitHub — 「내 연결」 없음과 연결 뒤

1. `claude -p "GitHub MCP의 get_me로 내 계정 정보를 알려줘."`
2. 기대(연결 전): `MCP-CREDENTIAL-001` 「GitHub 계정 연결이 없거나 만료되어 호출하지 않았습니다」.
3. 콘솔 **내 연결**에서 본인 GitHub 개인 액세스 토큰 연결 → 다시 실행 → `Allow`. 끝나면 해제할 수 있다.

### 3.3 출력 통제(원격 문서·긴 결과)

Windows에서는 파일 MCP 대신 긴 결과를 주는 원격 도구로 본다.

| 프롬프트 | 기대 |
| --- | --- |
| `claude -p "DeepWiki MCP의 read_wiki_contents로 pallets/flask 위키 전체를 읽고 절 개수를 세어 줘."` | `Allow`(긴 문서를 줄 수로 막지 않음). 바이트 상한을 넘으면 `MCP-OUTPUT-001` 「…byte 상한」이 정상 |
| `claude -p "Cloudflare Docs MCP로 'Workers KV 일관성'을 검색해 요약해."` | `Allow`(결과 속 타임스탬프 숫자를 카드번호로 보지 않음) |

로컬 파일 시험(긴 Markdown·가짜 키·숫자 ID JSON)은 Linux 매뉴얼 3.4를 따른다.

### 3.4 주소 인자가 있는 도구(허용 주소)

1. 관리자: **MCP 서버 → AWS Knowledge → 범위**에서 `aws___read_documentation`의 **허용 주소**에 `docs.aws.amazon.com` 기록.
2. 직원: `claude -p "AWS Knowledge MCP의 aws___read_documentation으로 https://docs.aws.amazon.com/AmazonS3/latest/userguide/example-bucket-policies-vpc-endpoint.html 을 읽고 4줄로 정리해."`
3. 기대: `Allow`. 허용 주소 밖 주소는 `PAC-01`.

### 3.5 동시 사용(같은 직원, PowerShell 두 개)

두 창에서 거의 동시에:

```powershell
claude -p "DeepWiki MCP로 microsoft/playwright 위키 목차를 보고 5줄로 요약해"
```

```powershell
claude -p "Microsoft Learn MCP로 Entra ID 조건부 액세스 문서를 검색해 4줄로 요약해"
```

기대: 둘 다 요청한 서버의 도구를 찾고 `Allow`. 「도구가 보이지 않는다」는 답이면 실패로 기록(시각 포함).

### 3.6 정책 변경 중 사용

1. 직원: `claude -p "DeepWiki MCP로 microsoft/vscode, microsoft/TypeScript, pallets/flask, vercel/next.js 위키 목차를 하나씩 차례로 조회하고 저장소마다 3줄로 요약해. 호출별 성공/차단 표를 만들어."`
2. 그동안 관리자가 **다른** 시험 서버를 승인하거나 철회한다(4절).
3. 기대: 직원 작업의 모든 호출 `Allow`(「rejected the credential」·`ENDPOINT-MANAGED-001` 없음). 새 서버는 1분 안에 트레이 승인 서버 목록에 반영.

## 4. 도입 수명주기(관리자·직원)

1. 직원: 콘솔 **도입 신청 → 새 신청**에서 원격 MCP 주소로 신청(예 `https://gitmcp.io/docs`).
2. 관리자: **도입 신청 → 검토** → 위험 등급·도구·허용 주소 확인 → 사용 대상 「전체 직원」 → **승인**(미리보기 뒤 15분 안에).
3. 직원: 1분 뒤 트레이 승인 서버 목록 확인 → 새 PowerShell에서 그 서버로 호출 → 동의 → `Allow`.
4. 관리자: **MCP 서버 → 그 서버 → 철회** → 직원 하네스에서 사라짐. 끝나면 철회 상태로 둔다.

## 5. 재설치·제거

| 시험 | 방법 | 기대 |
| --- | --- | --- |
| 재설치(업데이트) | 콘솔에서 새 `.cmd`를 받아 다시 실행 | 이전 설치를 원복한 뒤 다시 설치, 같은 PC·같은 직원이면 활성 상태를 이어받음 |
| 재부팅 | PC 재시작 후 로그인 | 트레이가 다시 뜨고 1분 안에 「연결됨」, `claude -p` 호출 `Allow` |
| 제거 | 콘솔에서 자격 폐기 → 트레이 **제거** → UAC | `C:\Program Files\ClaudeCode\managed-*.json`이 사라지고 하네스가 원래대로 동작 |

## 7. 고급: 격리 계정

마법사에서 「고급: 격리 계정」을 고르거나 콘솔에서 체크해 받는다. 별도 표준 계정 `mcpgw-<직원>`과 계정 범위 방화벽 규칙이 생기고 활성화는 관리자가 한다.
그 계정에서는 브라우저를 포함한 모든 프로그램이 게이트웨이 밖으로 나가지 못한다. 하네스 모델 로그인은 그 계정에서 한 번 한다. 3절을 반복한다.

## 8. 문제 해결

| 증상 | 확인 | 조치 |
| --- | --- | --- |
| 하네스가 「도구가 없다」고 함 | 트레이 승인 서버 목록 | 새로 승인된 서버면 PowerShell·하네스 재시작 |
| 401 「활성화를 기다리는 중」 | 콘솔 엔드포인트 상태 | 관리자 활성화 |
| 인증서 오류 | 설치 전 연 창인지 | 새 PowerShell(또는 다시 로그인) |
| 트레이 「연결 끊김」 | 트레이 **다시 연결** | 서비스가 멈췄으면 UAC 승인 |
| `P-CONSENT-001` 반복 | **이용 동의** 대기 항목 | 직원이 허용 |
| `.cmd` 실행이 막힘 | 조직 실행 정책 `AllSigned` | 조직 서명 배포가 필요(IT 문의) |
| 호출은 되는데 `MCP-SHADOW-002` 경보가 붙음 | 프롬프트에 `FastMCP`·`modelcontextprotocol` 같은 MCP 패키지 이름이 있는지 | Linux에서 확인된 오탐(관찰기가 하네스 명령줄을 미등록 MCP로 봄). Windows에서도 나는지 기록 |
