## D-301 정책 정의와 집행 증거를 분리해 조회한다 (2026-10-31)

- 이유: 관리대장에 운영으로 등록된 정책과 실제 실행 경로에서 집행되는 정책은 같은 사실이 아니다. 원본 오류 시 이전 캐시로 목록을 만들면 현재 로드 상태를 오해할 수 있다.
- 결정: 관리대장 API는 현재 OPA 문서를 직접 조회하고 조회 상태와 시각, 실행 규칙과 정책 데이터의 배포 대조, 최근 24시간 최종 판정 집계를 반환한다. 조직 단위 원장 집계가 추가되므로 관리자 인증을 요구한다. 집행 자체와 원장은 변경하지 않는다.
- 화면: 정책 목록의 집행 주체, 관리 상태, 정의된 결과, 원장 근거, 관련 POL을 분리한다. 상세에는 정의와 집행 근거 및 명시적 연결을 두며 감사 화면으로 이동한다. 서버 권한과 호출 원문을 중복 표시하지 않는다.
- 경계: 배포 해시 일치와 원장 기록은 현재 집행 경로 및 독립 효과의 검증이 아니다. pol_ids가 없는 정책은 POL 연결 미확인이다. 정책 충돌에서 선택되지 않은 규칙과 무효 표시된 기록의 유효성 판정은 집계에 포함하지 않으며, 집계는 최종 policy_id 원장 행 수만 의미한다.
- 검증: UI 93개, 격리 API 시험 6개 및 인증과 제품 문구 정적 검사. 실제 OPA 및 DB 연동, 솔루션 배포와 브라우저 검수는 미실행이다.
- 보고: research/llm-wiki/status/reports/2026-10-31-policy-evidence-ui.md

## D-302 조직 보안 정책 카탈로그는 실행 정책 및 적용 증거와 분리한다 (2026-10-31)

- 이유: 조직의 POL 전체 목록은 구현 규칙 목록과 다른 정보다. 별도 PaC 코드의 존재를 현재 게이트웨이에서 적용 중이라는 표시로 바꾸면 안 된다.
- 결정: 정책 원본과 구현 분류 및 Rego 판정 줄과 시험 정의에서 읽기 전용 제품 카탈로그를 재생성한다. 제품 이미지의 앱 디렉터리에 포함하고 기존 관리자 정책 API로만 제공한다. 원본이 없거나 잘못되면 조회 실패로 구분한다.
- 화면: 조직 보안 정책과 집행 규칙을 나눈다. 조직 정책은 대상, 적용 단계, 구현 방식, 코드 확인과 조직 적용 확인을 표시한다. 상세에는 본문과 통과 및 차단 요건, 시험 정의와 집행 규칙 검토 후보를 둔다.
- 경계: 과거 정적 분류의 구현 상태를 현재 적용 상태로 쓰지 않는다. 규칙 및 시험 정의는 실행 성공을 의미하지 않는다. 정적 검토의 후보 ID가 현재 관리대장에 있더라도 검토된 POL 매핑으로 승격하지 않는다. 원문 지시는 분석 데이터다.
- 검증: 원본 일치와 누락 및 손상된 카탈로그, 규칙 정의 추적 및 화면 이스케이프와 미확인 상태 시험. 기기 배포와 브라우저 검수는 미실행이다.
- 보고: research/llm-wiki/status/reports/2026-10-31-organization-policy-tab.md

## D-303 승인 작업은 처리 대상의 화면으로 이동한다 (2026-10-31)

- 이유: 단독 승인 대기 화면은 호출 승인, 실행 확인, 개인 이용 동의처럼 처리 주체와 목적이 다른 작업을 한곳에 섞는다.
- 결정: 호출 승인은 대시보드의 요약과 전체 목록 탭으로 옮긴다. 실행 확인과 승인 처리 이력은 호출 및 감사 기록으로 옮기고 본인의 이용 동의는 내 계정 메뉴 그룹에 둔다. 가입 승인과 엔드포인트 활성화 및 도입 신청은 기존 관리 화면에서 처리한다. 기존 승인 대기 주소는 새 화면으로 연결한다.
- 경계: 승인, 거부, 증빙 확인, 본인 요청 제한, 승인 번복 및 실행 확인 API는 유지한다. 개인 이용 동의를 관리자 대행 기능으로 확장하지 않는다. 감사 원장과 판정 규칙은 바꾸지 않는다.
- 검증: 메뉴 구성과 이전 주소 이동, 요약 5건과 전체 목록, 본인 요청 버튼 제한, 실행 확인 및 번복 버튼, 번역과 중대 영향 증빙 표시 관련 로컬 테스트 30개 통과. 실기기 배포와 브라우저 검수는 미실행이다.
- 보고: research/llm-wiki/status/reports/2026-10-31-approval-ui-relocation.md

## D-304 호출 통계와 현재 미해결 실행을 구분한다 (2026-10-31)

- 결정: 오늘 도구 호출에서 전체와 차단을 주요 지표로, 실행 건수를 보조 수치로 표시한다. 실행 미확인은 관리자 조치의 실행 확인 필요로 옮기고 기존 `dispatch.uncertain_count()`로 기간 제한 없는 현재 미해결 건수를 조회한다.
- 경계: 기존 실행 확인 목록과 같은 UNSETTLED 조건을 사용하며 목록 제한 200건과 관계없이 집계한다. 판정과 실행 확인 처리 절차는 변경하지 않는다.
- 검증: JS 구문 검사와 대시보드 및 번역 관련 검사 4개 통과. 실제 DB 연동, 기기 배포 및 브라우저 검수는 미실행이다.

## D-305 대시보드는 현재 조치 대상과 오늘 호출 규모를 구분한다 (2026-10-31)

- 결정: D-304의 표시 구성을 대체한다. 조치 필요 네 항목을 먼저 배치하고 오늘 도구 호출은 전체와 차단만 표시한다. 통제 정상 엔드포인트 수와 실행된 호출 보조 수치는 상단에서 제거한다. 요약 탭에 중복된 실행 확인과 기한 초과 건수는 제거한다.
- 집계: 실행 확인은 기존 미해결 조건, 통제 연결은 기존 우회 가능 상태, MCP 점검은 연결 오류와 계약 변경 및 확인 대기, 종료 조치는 모든 미종결 케이스를 사용한다. 종료 기한 초과는 미종결의 부분집합이다. 숫자를 합산하지 않는다.
- 이동: MCP 점검 목록은 동일 상태 조건으로 필터링한다. 종료 목록은 서버에서 미종결 또는 기한 초과 조건을 적용하고 50건씩 조회해 오래된 대상도 페이지 이동으로 확인한다. 인증 및 판정과 원장 기록 동작은 유지한다.
- 검증: 대시보드와 목록 필터 및 페이지 이동, 번역 관련 6개 검사와 종료 집계 및 목록의 격리 SQL 시험 3개 통과. Python과 JS 구문 검사 통과. PostgreSQL 통합 및 기기 배포와 브라우저 검수는 미실행이다.
- 후속 명칭 변경: 조치 필요를 확인 및 조치로, 네 항목을 실행 여부 확인, 연결 통제 점검, MCP 서버 점검, 종료 처리로 변경한다. 숫자 옆에 건 또는 개 단위를 표시하며 집계 및 이동 조건은 유지한다. 단순 문구와 표시 변경으로 JS 구문 검사만 수행한다.
- 후속 표시 정리: 요약 탭은 승인 및 등록, 호출 승인 요청, 최근 차단 10건, 시스템 자원 순서로 둔다. 호출 승인 건수 링크는 목록과 중복되므로 제거한다. 단순 순서와 문구 변경이며 JS 구문 검사만 수행한다.

## D-306 호출 승인 목록은 검토 후 실행과 전체 대기 조회를 제공한다 (2026-10-31)

- 이유: 기존 30건 제한을 전체 목록으로 표시하면 나머지 요청을 확인할 수 없다. 목록에서 즉시 실행하는 버튼은 상세 근거를 확인하는 흐름과 맞지 않는다.
- 결정: 기존 관리자 승인 API에 페이지와 전체 건수 및 가장 오래된 요청 시각을 추가한다. 만료가 가까운 순서로 조회한다. 요약은 첫 5건으로 줄이고 전체 탭에 사유와 요청 대상 요약을 표시한다. 목록은 검토만 제공하고 상세에서 승인과 거부한다. 일반 승인에는 실행 최종 확인을 추가한다.
- 갱신: 15초 간격으로 승인 목록만 갱신한다. 상세와 확인창, 목록 내 포커스를 보존하고 이전 화면의 늦은 응답을 무시한다. 오류를 빈 목록으로 바꾸지 않는다. 처리 후 사라진 마지막 페이지는 보정한다.
- 경계: 관리자 범위와 본인 요청 제한, 중대 영향 증빙 확인과 해시 검증, 거부 사유 및 처리 이력은 기존 동작을 유지한다. 승인 API와 실제 집행 권한은 확장하지 않는다.
- 검증: 승인 화면과 페이지, 갱신 경합과 오류 복구, 일반 승인 취소 및 확인, 중대 영향 증빙 전달과 번역의 관련 검사 11개, 격리 API 검사 3개 통과. 실제 DB와 브라우저 연동 및 솔루션 배포는 미실행이다.
- 후속 표시 변경: 사용자 요청으로 요약의 승인 요청 미리보기와 관련 렌더링 분기를 제거했다. 요청 목록은 호출 승인 탭에서만 표시한다. 승인 처리와 페이지 이동은 유지하며 단순 표시 변경으로 JS 구문 검사만 수행했다.

## D-307 연결 통제 분포와 점검 목록은 AI 연결 관리에 모은다 (2026-10-31)

- 결정: 대시보드의 통제 적용 현황 탭을 제거하고 분포 그래프를 AI 연결 관리의 연결 목록 상단으로 옮긴다. 점검 연결 최대 8건 미리보기와 사용자 및 엔드포인트 영향 범위 추정은 기존 연결 목록과 중복되므로 제거한다. 상단 점검 건수와 필터 이동은 유지한다.
- 경계: 분포는 기존 중복 제거 기준의 연결 항목 수다. 통제 판정과 증거 분류를 변경하지 않는다. 그래프와 목록은 같은 스냅샷을 사용하며 선택한 유형과 상태로 필터링한다. 옛 대시보드 탭 주소는 새 위치로 연결한다.
- 검증: 이전 주소, 탭 제거와 그래프 이동, 중복 제거 집계와 그래프 필터 선택, 번역 관련 검사 4개 및 JS 구문 검사 통과. 실제 배포와 브라우저 검수는 미실행이다.

## D-308 호출 분석은 원장 조회와 같은 필터로 한곳에 제공한다 (2026-10-31)

- 결정: 대시보드의 호출 분석 탭을 제거하고 호출 및 감사 기록의 분석으로 통합한다. 기존 호출 추이는 유지하고 정책별 차단과 경보, 엔드포인트별 호출 및 하네스별 판정을 추가한다. 목록과 분석에서 같은 필터를 조작할 수 있으며 기본은 최근 24시간의 도구 호출이다.
- 집계: 기존 분석 API에 동일 WHERE 및 사용자 범위를 사용하는 집계를 추가한다. 엔드포인트는 현재 등록 상태와 무관하게 원장 식별자로 집계한다. 상위 차원 12개와 기타로 합계를 보존하고 마지막 호출 시각을 제공한다. 연결 이벤트는 별도 선택할 수 있다.
- 경계: 관리자 추가 화면과 직원 본인 범위를 유지한다. 하네스는 기록된 이름이며 신원이나 판정 근거로 승격하지 않는다. 정책별 통계는 정의 및 적용 증거를 대신하지 않는다. 기존 overview 응답 필드는 호환성을 위해 유지한다.
- 동작: 분석 새로고침은 차트와 엔드포인트 표를 함께 갱신한다. URL에 필터를 반영해 재조회 시 이전 값으로 돌아가지 않게 하고, 이전 조건의 늦은 응답은 적용하지 않는다. 기존 대시보드 호출 분석 주소는 새 위치로 연결한다.
- 검증: UI와 이전 주소, 기간 및 필터 공유와 갱신 경합, 직원 화면 및 번역 관련 검사 8개와 격리 SQL 집계 검사 3개 통과. 실제 PostgreSQL 통합과 배포 및 브라우저 검수는 미실행이다.

## D-309 성능 화면은 호출 시간과 엔드포인트 통신 측정을 분리한다 (2026-10-31)

- 결정: 지연 탭의 내부 키는 유지하며 명칭을 성능으로 바꾼다. 전체, 게이트웨이 자체 처리, MCP 통신과 처리 시간을 중앙값과 95백분위 및 측정 건수로 표시한다. 구간별 표에 측정 호출 수를 추가한다. 조회 실패를 측정 없음으로 바꾸지 않는다.

- main 통합: 통제 현황은 별도 페이지로 유지하며, 최신 기본 기능 및 커넥터 통제와 엔드포인트 통제 점검 및 MCP 설정은 각각 통제 현황과 엔드포인트 관리에 반영한다.

- 근거: 소유자가 계정 관리와 PC 관리의 메뉴 분리를 요청했다.
- 결정: people에는 계정, 가입 요청, 이용 중지, SSO를 유지하고 endpoints에는 PC 등록, 활성화, 연결 이력을 둔다. 두 페이지 모두 기존 관리자 권한을 요구한다. 기존 엔드포인트 탭 주소는 새 페이지로 연결한다.
- 검증: 페이지별 렌더링과 데이터 요청 분리 시험, 기존 번역 및 상태 시험, 인증 정적 검사 통과. 실제 기기 배포와 브라우저 검수는 미실행.

## D-321 통제 현황을 연결 관리와 엔드포인트 관리로 통합 (2026-10-31)

## D-322 콘솔 CI의 만료된 시험 권한과 관리 조회 연결을 분리한다 (2026-11-01)

- 근거: `0b395937`의 GitHub 검증에서 정상 호출 9개가 PAC-01로 차단됐다. 랩 capabilities의 고정 만료 시각이 지났으며 대시보드의 새 실행 확인 건수 조회는 관리용 풀 검사에도 실패했다.
- 결정: 대시보드는 기존 실행 확인 조건을 관리용 fetch_one으로 조회한다. 기본 호출은 판정용 풀을 유지한다. 일회용 GitHub CI의 기본 랩 레지스트리에만 실행 시각 전 1분부터 이후 1일까지의 시험 유효기간을 준비한다. 승인된 주체와 도구, 자원 및 인자 범위는 바꾸지 않는다.
- 경계: field와 deploy 레지스트리, 운영 권한 및 PAC 만료 판정은 변경하지 않는다. 준비 스크립트는 GITHUB_ACTIONS와 CI가 true인 실행만 허용하고 입력 경로를 기본 랩 파일로 고정한다. 독립 검토의 과거 해시와 실행 증거를 현재 검증으로 바꾸지 않는다.
