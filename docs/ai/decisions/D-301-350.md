# 설계 결정 번호 301~350

## D-301 Codex 허용 목록은 비어 있어도 표를 두고, 모든 MCP 호출은 관리형 훅으로 중앙에 남긴다 (2026-10-31)

- 증상: pj3(Windows 11)에서 Codex가 미등록 Ghidra MCP(pyghidra-mcp)를 켜 도구 4개를 호출했지만 중앙에는 인벤토리 `shadow` 행만 남았다. 호출 기록·경보·감사가 없었다.
- 원인 1: Codex `requirements.toml`의 `[mcp_servers]` 표가 없으면 제한하지 않고, 있으나 비면 전부 끈다(learn.chatgpt.com managed configuration). 승인 서버가 0개인 장치에는 표가 빠졌다.
- 원인 2: 경보는 게이트웨이 호출 판정에서만 만들었다. 로컬 MCP·커넥터 호출은 게이트웨이를 거치지 않는다.
- 결정: 엔드포인트 정책·실기기 키트·실습 워크스테이션 렌더러가 빈 `[mcp_servers]` 표를 항상 둔다. Claude Code `managed-settings.json`과 Codex `requirements.toml`에 `PostToolUse` 훅(`mcp__*`)을 넣는다. 훅은 키트 `agent.py hook`이 직원 홈 `.mcpgw/tool-events.jsonl`에 서버·도구 이름, 인자 크기·SHA-256, 결과 크기, 실패만 남기고 서비스가 `/api/endpoint/tool-events`로 보낸다. 중앙 `endpoint_tool_events`는 경로(게이트웨이·커넥터·로컬)를 붙인다. 로컬 경로 첫 호출, 엔드포인트가 보고한 미등록 설정·확인된 수신기는 `unapproved-endpoint-mcp` 경보(SIEM 큐 포함).
- 셸: Windows Codex는 훅을 PowerShell로 실행해 `&` 호출 연산자가 필요하고, Claude Code는 `command`+`args`로 둔다.
- 대안: stdio 중계(설정 재작성)는 레퍼런스(Obot Sentry·Runlayer·Endor·Mintive)가 관리형 훅을 쓰는 것과 달리 설정 충돌과 우회 재작성이 생겨 보조로 미뤘다.
- 검증: pj3 — 빈 표 뒤 `ghidra … disabled: requirements`, Codex ChatGPT 앱 호출 → `hook: PostToolUse Completed` → 콘솔 「엔드포인트 호출」. 실제 PostgreSQL 랩 경보 시험.
- 한계: 기록 파일은 직원이 지울 수 있다. Claude Code 훅의 Windows 실행은 미확인. PreToolUse 차단 모드 미구현. 설계서 [OVERHAUL_2026-10-31](../OVERHAUL_2026-10-31.md).

## D-302 엔드포인트 사용자 기능은 한 명령 표를 CLI와 로컬 화면이 같이 쓴다 (2026-10-31)

- 결정: `mint servers·logs·request·login·ui`. 표는 `kit_access.py` 하나이고 Windows `mint.cmd`·Linux `mint`가 하위 명령을 넘긴다. 직원 계정은 서비스의 기존 로컬 통로(파이프 DACL·소켓 SO_PEERCRED)에 더한 `self`·`request` 동작으로 `/api/endpoint/self`·`/api/endpoint/self/requests`만 부른다. `mint ui`는 127.0.0.1 임시 포트·경로 토큰·스크립트 없는 화면, 30분 유휴 시 종료.
- 도입 요청은 `endpoint_mcp_requests`에 쌓이고 관리자가 콘솔 「도입 신청 > 엔드포인트 요청」에서 미리 채운 신청서로 잇거나 닫는다. 엔드포인트가 스스로 등록하지 않는다.
- Codex 앱 내장 런타임(`cua_repl`·`node_repl`)은 벤더 설치 경로면 인벤토리에서 뺀다. BOM이 붙은 하네스 설정도 읽는다.
- 참고: `tailscale web`(localhost 화면), NetBird(CLI·앱 같은 상태).
- 검증: pj3 실기기 `mint servers`·`logs`·`request`·`ui`(네 화면), 콘솔 요청·신청서 미리 채움, 실제 PostgreSQL 랩 8/8.
- 한계: Windows 관리형 장치는 하네스 커넥터·기능 보고를 아직 보내지 않는다. 자가 복구 명령 미구현.

## D-303 커넥터는 기본 승인·발견 시 목록·중앙 차단, 하네스 기본 기능은 커넥터에서 분리한다 (2026-10-31)

- 결정: `/api/integrations`에서 하네스 기능(`kind=feature`)을 빼고, 「MCP 서버 > 커넥터」에는 커넥터만, 「정책 > 하네스 기능」에 기능 켬·차단을 둔다. 기본 승인 커넥터는 「관찰만」 경고 대신 「기본 승인 · 벤더 경유」. 미등록 MCP는 이름별 한 항목.
- 근거: Claude 조직 설정(Capabilities와 Connectors), ChatGPT(설정과 Connectors 탭), Codex(`[features]`와 `[mcp_servers]`)가 모두 둘을 나눈다.

## D-304 콘솔 첫 화면·경보·종료 화면 정리 (2026-10-31)

- 결정: 상단 경보 종과 「호출·감사 기록 > 경보」(`/api/audit/alerts`), 대시보드 요약에 시간대별 판정·MCP 서버별 호출 그래프와 처리할 일·최근 경보·한 줄 차단 목록, 작은 숫자 줄을 기본. 종료·폐기는 서버 이름 제목, 결과는 「완전 종료·부분 종료·종료 확인 불가」, 기준은 이름(모집단 등)으로.
- 근거: NN/g·Carbon 대시보드(그래프·핵심 지표 소수), Cloudflare·Tailscale 콘솔 흐름(개요 → 목록 → 상세 → 조치).

## D-305 개편 단계 (2026-10-31)

- 1단계 D-303·D-304, 2단계 D-301, 3단계 D-302. 각 단계는 :8000 기기 배포와 pj3 실측으로 닫는다. 남은 것: Windows 하네스 커넥터·기능 보고, 자가 복구, PreToolUse 차단 모드, 7일 그래프, 재등록으로 생긴 옛 엔드포인트 정리.
