# 보안 운영 콘솔 UX 개선과 검증 기록

이 변경은 `full_stack_lab/gateway/app/agent_static`의 실제 콘솔과 로그인 화면에 적용한다. 운영자가 첫 화면에서 상태와 수치를 확인하고, 주의가 필요한 판정을 찾아 감사 기록으로 이어갈 수 있도록 구성했다. 인증과 정책 집행은 기존 서버가 담당한다.

## 화면과 동작

- 핵심 지표와 주의 항목을 긴 판정 목록보다 먼저 보여준다. 호출 처리 경로 설명은 하단에서 펼칠 수 있다.
- 도구, 정책, 주체, 역할, 추적 ID로 판정을 검색한다. 판정 필터와 함께 사용할 수 있다.
- 목록 일시정지는 화면에 표시된 행을 고정한다. 수신은 계속하며 재개하면 최신 판정으로 전환한다. 다른 지표까지 정지하는 기능은 아니다.
- SSE의 실제 응답 `{rows, cursor}`를 읽는다. 기존 화면은 `decisions`만 읽어 이 이벤트를 놓치고 있었다. ID로 중복을 제거하고 최신 40건을 유지한다.
- 판정 분포 막대는 `style-src 'self'` CSP 때문에 인라인 너비가 무시되던 결함을 네이티브 `<progress>`로 수정했다. 수치와 최댓값이 보조 기술에도 전달된다. 실시간 판정의 작은 막대 높이도 CSS 속성으로 옮겼다.
- 전체 조회와 실시간 수신이 겹쳐도 새 행을 잃지 않는다. 첫 이벤트가 빈 조회 응답보다 먼저 도착한 경우도 처리한다.
- 마지막 성공 시각, 갱신 중, 갱신 실패, 스트림 재연결을 구분한다. 조회 실패 시 기존 데이터를 보존하고 지속적인 안내와 새로고침을 제공한다.
- 입력 중인 탐색 정책과 장치 소유자 선택을 갱신으로 덮어쓰지 않는다. 도구 요청과 도입 신청은 처리 중 중복 제출을 막고, 한글 조합 중 Enter를 전송으로 처리하지 않는다.
- 메뉴 이동 시 제목으로 초점을 옮긴다. 본문 건너뛰기와 브라우저 뒤로 가기를 지원한다. 모바일 메뉴는 Escape로 닫고 열기 버튼으로 초점을 돌려준다.
- 390px 화면에서 메뉴를 접고, 표는 이름 있는 스크롤 영역으로 제공한다. 작은 화면의 버튼은 최소 44px 높이를 사용하고 동작 감소 설정을 따른다.

## 수치와 보안 의미

| 표시 | 의미와 범위 |
| --- | --- |
| 최근 판정, 판정 분포 | 서버에서 조회하고 실시간으로 받은 최근 최대 40건. 오늘 전체 통계가 아님 |
| Block 판정 | 입력 또는 출력 정책의 차단 판정. 실행 전 차단만을 뜻하지 않음 |
| 누적 실행 증적 | 서버의 독립 upstream 효과 카운터. 최근 판정 수와 분모가 다름 |
| 실행 여부 미확인 | `upstream_attempted`이 참이고 `upstream_executed`가 거짓인 기록. 실행 성공으로 세지 않음 |
| 승인 대기 기록 | `/api/console`의 PENDING 기록. 만료 기록이 포함될 수 있으며 승인 가능 건수와 같지 않음 |
| 상태 미확인 | 상태가 없거나 지원하지 않는 값. 정상으로 추정하지 않음 |

출력 차단은 `실행 후 출력 차단`으로 표시한다. 승인 대기 기록에 실제 승인 버튼을 추가하지 않았다. 승인은 도구 실행을 유발하므로 별도의 요청 상세와 승인 UX가 필요하다.

메뉴와 이동은 서버의 `viewer.pages`를 따른다. 새로 조회한 사용자 또는 역할 범위가 바뀌면 이전 판정 캐시와 화면 데이터를 비우고 스트림을 다시 연결한다. 브라우저의 표시 제어가 서버 권한 검사를 대신하지 않는다. 집행 모드 변경은 영향 설명을 읽고 확인한 후 기존 API로 요청한다.

## 다섯 관점의 교차 검토

| 검토 관점 | 발견 또는 결정 | 반영 및 재확인 |
| --- | --- | --- |
| UX와 레퍼런스 | 지표가 긴 목록 아래에 묻힘, 승인으로 이어지지 않는 이동의 위험 | 지표 우선 배치, 감사 필터 전달, 승인 기록의 범위 표시 |
| 시각 디자인 | 상태 대비, 좁은 화면의 메뉴와 필터 배치 | 공통 색상과 간격, 테마별 대비, 모바일 메뉴와 표 |
| 접근성 | 이름 없는 입력, 자동 갱신 초점 유실, 오래된 데이터 안내 부재 | 입력 이름, 초점 관리, 편집값 보존, 지속 오류 안내 |
| API와 기능 | SSE 응답 계약 불일치, 빈 조회 응답과 첫 이벤트 경합 | 실제 응답 파싱, ID 병합, 요청 시작 커서 기준 보존 |
| 회귀 테스트 | 잘못된 행과 상태 값이 예외 또는 부정확한 표시를 만들 수 있음 | null 행 처리, 미지원 상태 처리, 자동 테스트 추가 |

UX와 접근성 검토 결과를 시각 디자인에 전달했고, API 검토 결과를 상태 테스트와 대조했다. 구현 후 기능 검토에서 발견한 본문 건너뛰기 라우팅, 실시간 갱신의 초점 유실, 빈 응답 경합을 수정한 뒤 재검토했다.

## 검증

자동 검사:

```bash
node --check full_stack_lab/gateway/app/agent_static/console.js
node --check full_stack_lab/gateway/app/agent_static/login.js
node --test full_stack_lab/tests/console-state.test.mjs
python3 full_stack_lab/tests/open_endpoints.py
git diff --check
```

상태 회귀 테스트 11개가 통과했다. 실제 SSE 응답 구조, 숫자 ID 정렬과 중복 제거, 40건 상한, 검색 조합, 출력 차단, 불명확한 연결 상태, 빈 응답 경합을 포함한다. HTML ID 중복과 ARIA 참조도 검사했다. GitHub Actions의 정적 검사에 Node 24 설정과 콘솔 검사 단계를 추가했다.

브라우저 검증은 실제 HTML, CSS, JS를 제공하는 로컬 서버와 합성 API 응답으로 수행했다. 외부 API나 실제 MCP 실행은 사용하지 않았다.

| 확인 항목 | 결과 |
| --- | --- |
| 1440×1000 운영 화면, 밝은 테마와 어두운 테마 | 배치와 상태 색상 확인 |
| 390×844 화면 | 운영, 도입, 정책, 신원, 엔드포인트, 감사, 실행, AI 감사에서 문서 가로 넘침 없음 |
| 검색과 Block 필터 → 감사 이동 | 검색어와 판정 유지, 실행 후 출력 차단 표시 |
| 일시정지 후 새 이벤트 3개 수신 | 목록 24개 고정, 새 판정 3개 안내, 재개 후 27개 표시 |
| 최신 ID 43 수신 후 ID 40까지의 이전 조회 응답 | ID 43 유지, 중복 없음 |
| 탐색 정책 편집 후 새로고침 | 입력한 대역과 변경 상태 유지 |
| 서버 조회 실패 | 기존 27개 판정 보존, 마지막 성공 시각과 지속 오류 안내 |
| 관리자 → 직원 응답으로 변경 | 관리자 메뉴와 이전 운영 판정 제거, 허용된 화면으로 이동 |
| 알려지지 않은 health 값 | 상태 미확인 표시 |
| 요청 처리 중 Enter 재입력 | 사용자 요청 1개만 표시 |
| 모바일 메뉴, Escape, 본문 건너뛰기, 뒤로 가기 | 초점과 화면 이동 확인 |
| 빈 데이터와 도입 필수 입력 누락 | 빈 이유 안내, 첫 잘못된 입력으로 초점 이동 |

기존 PR의 검증은 UI와 합성 응답 기준이었다. 통합 후 2026-09-25 WSL Docker 스택에서 `./console.sh test`가 통과했다(`acceptance` 95/0, `agent-acceptance` 106/0, `runtime-acceptance` 49/0). 로그인한 실제 Console의 최근 40건은 Allow 5, Alert 5, Restrict 2, Approval 3, Block 25로 표시됐고, `<progress>`의 `value/max`가 각각 5/25, 5/25, 2/25, 3/25, 25/25였다. 브라우저에서 막대 길이 차이를 시각적으로 확인했다. 390px 모바일 화면은 `scrollWidth=390`, 탐색 메뉴 열기·Escape 닫기와 초점 복귀를 확인했다. 합성 응답은 운영 효과나 실제 모델 검사 성공 증거가 아니다.
