## 변경과 판단

| 범위 | 확인한 의미 | 검증 경계 |

| PAC15 공급자 위치 재심사 | `core.review_server_residency`는 신청자와 심사자의 독립성을 확인한 뒤 승인 사건을 먼저 기록하고 등록부 위치와 심사 결속 해시를 저장한다. `residency.transfer_review_digest`는 서버 ID, 엔드포인트, 도입 신청, 위치 다섯 항목, 전체 관할 규칙 팩에 결속된다. `facts`는 호출 시 현재 값과 대조한다. | OPA의 면제는 관할 팩이 활성이고 위치 및 이전 근거가 확인된 비중요 등급 서버의 국가별 승인 요구에만 적용된다. 중요 등급, 금지 국가, 도구의 별도 외부 목적지, 다른 PAC 검사는 계속 별도다. 감사 사건은 파일 반영과 배포 성공을 뜻하지 않는다. 법적 근거의 실제 적절성은 사람이 심사해야 한다. |

이전 검토 참조 중 6개 파일의 고유 참조 25개가 파일 해시와 맞지 않았다. 각 심볼의 이전 및 현재 행과 AST, 파일 전체 변경을 대조했다. PAC15와 PAC23에는 새 변경 함수 참조 4개, 변경되지 않은 호출 함수 참조 1개, 관련 시험 소스 참조 3개를 추가했다. 기존 증거 E01부터 E19까지는 과거 판본의 수준과 한계를 그대로 보존했다. 이번 단위 시험 결과를 실제 MCP, PJ1 또는 현재 배포 검수로 승격하지 않았다.

## 검증

로컬에서 `threat_trace_mapping_check.py` 4건, 위치 심사 대역 시험 10건, 로컬 이용 중지 대역 시험 12건, 직원별 중지 24건, 일괄 중지 14건, 위치 정규화 시험 8건이 통과했다. OPA 1.21.1의 `opa test full_stack_lab/opa --count 1`은 130/130 통과했다. 위키 검사에서는 무시된 로컬 원본 누락 경고와 별도로 오류 0건을 확인했다. 이 결과는 정적 추적, 정책 단위 시험, DB 및 등록부 대역의 범위다. 실제 PostgreSQL, 공개 MCP, 솔루션 기기, PJ1의 현재 실행은 확인하지 않았다.

원본 정책 ID `PAC01`부터 `PAC24`와 런타임 정책 ID는 다른 체계다. 24행 모두 현재 코드 후보를 가리키지만 전체 요구 충족이나 법적 판단 완료를 뜻하지 않는다. 다음 검수에서는 승인 전후의 실제 전송 판정, 관할 팩 변경, 도구 외부 목적지, 직원별 로컬 실행의 정지 및 재개 경합을 지정 기기와 PJ1에서 확인해야 한다.
