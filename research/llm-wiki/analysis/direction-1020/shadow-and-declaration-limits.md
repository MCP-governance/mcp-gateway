# 선언 계약의 분석 한계와 섀도 MCP 통제 범위

- 기준: 브랜치 `10/20-shadow-controls`, 시작 커밋 `ab3ac29a08e992d605502be87656dde8a201981d` (`origin/main` 추적). 문서 분석이며 코드·정책·배포를 바꾸지 않았다.
- 관련 방향: [통제 방향 검토](control-review.md), [엔드포인트 MCP 안전 경계](../../../../docs/ai/SECURITY_BOUNDARIES.md), [D-170](../../../../docs/ai/DECISIONS.md).
- 증거 구분: 아래 코드 위치는 현재 작업 트리에서 읽었다. 과거 기기 보고서는 해당 보고서의 당시 범위만 가리키며, 현재 커밋 배포나 모든 기기에서의 통과를 뜻하지 않는다.

## 1. 선언 계약이 보여 주는 것과 놓치는 것

게이트웨이는 MCP 서버의 도구 설명, 입력 스키마, 출력 스키마, 서버 판본을 관측·승인본과 비교한다. 이 값은 서버가 스스로 내놓는 선언이다. 함수 본문, 사용하는 자격, 파일 접근, 외부 부작용, 설명과 다른 실제 처리까지 게이트웨이가 분석하지는 않는다. 따라서 계약 일치와 승인 판정은 도구 동작의 안전성 증명이 아니다.

| 범위 | 코드 근거와 현재 동작 | 잡는 것 | 잡지 못하는 것·한계 |
| --- | --- | --- | --- |
| 서버·도구 등록과 일부 도구 승인 | `full_stack_lab/registry/catalog.toml`은 서버별 도구·권한을 선언한다. `full_stack_lab/gateway/app/registry.py:135-145`는 승인 도구와 도입 등록의 도구별 심사 범위를 반환한다. `full_stack_lab/gateway/app/pac.py:119-145`는 호출 주체에게 보일 도구를 제한한다. | 사람의 계약 심사를 거친 이름·권한만 목록에 내고, 도입 등록은 미심사 도구를 노출하지 않는다. | 이름과 r/w/x·목적·자산 표기가 실제 코드의 행위를 설명한다는 보장은 없다. 선언된 권한 이하의 악성 동작이나 허용된 도구의 숨은 부작용을 판정하지 않는다. |

## 3. 섀도 MCP 상태와 현재 통제

발견 열은 설정 수집(`user_command_settings` 포함), 프로세스, 리스너/네트워크, 게이트웨이 카탈로그를 구분한다. 설정 수집은 보고한 엔드포인트의 관리 계정 설정 파일 범위를 뜻한다. 모든 사용자·클라우드 커넥터·복사된 하네스까지 전수 조사하는 기능으로 읽지 않는다.

### 현재 코드에서 읽은 발견 채널

- 설정 인벤토리는 등록 엔드포인트가 제출한 항목만 저장·레지스트리 대조한다(`endpoint_plane.py:285-350`). 설정 수집기의 사용자 명령 설정 검사는 관리 계정 홈의 지정 파일 경로에 한정되며, 당시 구현 보고서도 설정·인자·클라우드 실행 등 모집단 밖과 배포/PJ1 미실행을 명시한다([보고 §결과·한계](../../status/reports/2026-10-20-user-command-settings.md)).
- 프로세스·리스너 수집은 별도 채널이고, 수집원/스냅샷의 완전성에 의존한다(`endpoint_plane.py:1024-1135`). `tools/list` 업스트림 대조는 Gateway가 관리하는 승인 서버에 한정된다(`core.py:222-267`). 서로 다른 세 관측을 하나의 전수 탐지 증거로 합치지 않는다.
- D-155는 MCP 요청 자체가 아니라 실행기 프록시의 목적지 접속 이벤트를 수집한다(`server_egress.py:26-57`). 요청 ID가 없어 연결은 보조 상관으로만 표시한다(`server_egress.py:60-83`).

## 4. `control-review.md`와의 대조

방향 판정과 어긋나는 변경 제안은 없다. 게이트웨이의 순차 판정·고정 계약·차단 우선(P7), 엔드포인트 관측/통제 범위, D-170의 조직 통제 의존 분류를 그대로 따른다([control-review §1–4](control-review.md)).

덧붙이는 범위 한계는 다음과 같다. 코드상 설정·프로세스·리스너 수집은 등록된 장치가 제출한 표본이며, 모든 계정이나 복사본을 발견하지 않는다. 게이트웨이의 `tools/list`는 관리 서버의 선언 대조다. 따라서 “섀도 서버 발견”을 전사 전수 발견으로 표시할 수 없다. 특히 Windows의 비인가 로컬 MCP 차단은 RM-01 재검토 항목대로 OS 강제라고 부르지 않고, 관리형 설정과 조직 통제 의존 범위로 표시한다.

## 5. 이번 작업 검증 경계

- 읽은 코드·설계·기존 보고서만 근거로 정리했다. 새 시험·실기기 호출·배포·화면 검증은 실행하지 않았다.
- 코드 변경 금지 조건에 따라 소스·기존 시험 기대값은 수정하지 않았다. 기존 시험 변경 필요: 없음.
- 새 D-번호를 만들지 않았다. 지정된 결정 번호가 없고 이 문서는 현행 설계 경계의 분석이다.
- 일부 줄 번호는 분석 기준 코드에서만 의미가 있다. 보고서의 예전 배포 커밋/기기 결과는 이 브랜치 커밋의 검증으로 승계하지 않는다.
