# Drive 정책·MVP WBS의 개발 연결

통합 대상 `10/15-drive-wiki-curation`의 `c0b6641`·`1ad6395`를 `e61e43c` 기반 문서 작업 브랜치에 fast-forward로 통합했다. 제품 코드 변경은 없다. 원본은 재저장·매크로 실행·수식 재계산 없이 읽었다.

## 새로 들어온 것과 기존 자료의 관계

| 자료 | 이번 대조 결과 | 개발 활용 |
| --- | --- | --- |
| 정책50 XLSM | 기존 50개와 정책 ID·명칭·본문의 공백 제거 대조 50/50 동일. 파일 바이트는 다른 판본 | 신규 요구 50개로 합산하지 않고 출처·기준 판본 보존 |
| MVP WBS XLSX | 6영역·24개 기능 계획, 2개 시트. 적용 OSS는 계획 | 현행 G01~G10의 40개 검수 작업과 의미별 연결 |
| 프레임워크 V3.0 | Drive curation 문서의 원문 링크·절차 요약을 사용 | 도입→승인→실행→운영→종료의 업무 절차 참고 |
| 실증 자료 | 해당 선별 시점에 평가 보고서·실행 데이터가 없었다는 원 보고 | 현재 부재나 시험 성공으로 확대 해석하지 않음 |

[원본 선별 문서](../../team-agi-deliverables-2026-10-15.md), [원본/캐시 셀 대조](workbook-review.json), [50개 판본 비교](policy-version-comparison.json)를 함께 읽는다. 이름·본문의 공백 제거 동일성은 법령·표준 근거 셀의 동일성·최신성이나 법적 적용성을 입증하지 않는다. 이번 작업에서는 Drive 원격 폴더를 다시 조회하지 않았다.

## 정책50에서 우선 확인할 개발 공백

- POL-10·24·26·40: 빈 목적지·복합 입력·redirect·DNS·서버 outbound를 DEV-41/44에 연결한다.
- POL-14·17: credential helper와 하네스가 시작하는 훅 명령의 경계를 DEV-42에서 검수한다.
- POL-20: 현재 검증할 수 없는 agent 위임은 거부한다. 진짜 에이전트 위임 지원으로 완료 처리하지 않는다.
- POL-32~35: 실행물 provenance와 문서 출처/진위, 서버 간 정보 흐름, 업무 컨텍스트, 대량 문서 조회는 서로 다른 통제다. Gateway의 원장·도구 allowlist만으로 충족하지 않는다.
- POL-44~50: 요청 차단, 프로세스 정지, SaaS 자격·문서 공유 회수, 임시 파일·제공자 데이터, 복원 뒤 재활성화를 분리한다. DEV-38의 수명 관리와 기존 종료 모델을 함께 검수한다.
