## 결론

**반려(C)를 유지한다.** `10/20-dev73-impl`은 수정·재검토 전에 병합·기기 배포·PJ1 시험으로 넘기지 않는다. 다만 F1은 검토가 제시한 두 선택지 중 **두 번째(위협 범위 명시)** 를 택한다.

## 항목별 처리

| 발견 | 처리 | 근거 |
| --- | --- | --- |
| F1 서명되지 않은 작업 본문 | **구현하지 않는다.** 게이트웨이와 분리된 작업 서명 키·1회용 작업 증명을 만들지 않는다. 대신 `SECURITY_BOUNDARIES.md` 위협 모델과 설계 문서에 "장치 실행기는 게이트웨이가 발행한 작업을 신뢰하며, 로컬 격리는 침해된 게이트웨이를 막지 않는다"를 명시하고 DEV-73 완료 조건에서 해당 주장을 뺀다. | 현행 위협 모델(4장)의 주체는 직원·악성 도구 설명·침해된 MCP 서버·정책 편집 가능한 단말 관리자이며 **침해된 게이트웨이는 포함되지 않는다**. 게이트웨이+OPA는 신뢰 기준점이다. 모델 밖 적을 막는 새 키 체계를 넣는 것보다, 막지 못하는 것을 막는다고 적지 않는 것이 정확하다(과대 주장 금지). |
| F2 철회·종료 뒤 대기 작업·과거 서명 재생 | **수정 필수.** claim·실행 직전 장치에서 정책 세대·서버 lifecycle·승인 매니페스트 해시·철회 상태를 재확인하고, 철회·종료와 큐 취소·실행 정지를 같은 전환에 결속한다. | 침해 없는 정상 운영의 경합이며 "실패는 차단으로"·종료 차단 우선·C1~C4 연속성 불변식에 직접 어긋난다. |

DEV-73의 완료 조건에서 "게이트웨이 침해 시에도 승인 밖 실행 0"을 빼고, "승인 매니페스트 밖 로컬 실행 0 · 컨테이너 외부 연결 0 · 철회·종료 뒤 실행 0 · 원격과 같은 형식의 원장"으로 둔다. 수정 후 새 적대 검토(luna)를 거친 뒤에만 기기 배포·PJ1로 넘어간다.
