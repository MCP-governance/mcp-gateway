## 결과

`endpoint-agent/managed-macos.py`, `install-macos.sh`를 추가했다. 설치는 기존 `install.sh`에서 Darwin으로 분기한다.
명령 한 줄과 sudo 관리자 암호 한 번으로 공식 PSF 서명 Python 런타임 확인/설치, dscl 일반 관리 계정 생성, 공식 native
Codex·Claude 탐색/복사, 관리형 설정, shim·셸 함수, pf, launchd를 연결한다. Python 외 새 제품 의존성·자체 MCP 추가 없음.
공식 하네스 기설치는 D-71과 같다. 서비스 코드는 Intel Homebrew가 소유할 수 있는 `/usr/local`을 피한
`/Library/MCPGatewayManaged`에 두며 shim은 요구한 `/usr/local/bin`을 사용한다.

기존 `bootstrap.py`의 하네스 탐색·교체 저널·shim/셸 함수를 재사용한다. `managed-linux.py`의 TLS 전송·정책 적용·
heartbeat·헤더 반환 루프도 재사용하며 Darwin adapter가 파일 경로·pf 점검·실제 계정 보고·getpeereid UID 검증을 제공한다.
장치 비밀은 root 전용 파일, 하네스 설정은 헤더 헬퍼 명령만 사용한다. 토큰 발급/캐시 갱신은 브로커 잠금 안에서 수행한다.

`KIT_FILES`·`/api/pc-kit`·`/auth/me`에 macOS를 반영했다. 기존 POST 다운로드에 `delivery=command`를 추가하고
5분·1회용 다운로드 자격을 헤더 파일로 전달한다. 등록 토큰과 해시 도메인을 분리하고 DB의 원자 UPDATE로 소비한다.
자격은 명령 문자열·URL query·환경·로그에 쓰지 않는다. 연결 파일은 실행 즉시 삭제하고 curl 설정·키트 압축 파일은 임시
전용 디렉터리에서 삭제한다. curl은 고정 CA·HTTPS를 사용하며 리다이렉트를 따르지 않는다. 콘솔은 OS별 연결 버튼을 정렬하고
macOS 터미널 명령·관리자 암호 횟수·유효 시간만 라벨/값으로 표시한다.

등록 모델·플랫폼 보존·정책·활성화 점검·통제 범위의 macOS 분기도 추가했다. macOS가 Linux AppArmor/nft 성공을
허위 보고하지 않으며 pf·설정 보호·일반 계정·사용자 명령 설정의 실제 항목만 요구한다. 다른 관리자 계정의 우회 가능성도 보고한다.

rollback은 launchd → shim/셸 함수 → 실행기/헬퍼 → pf anchor/자기 활성화 참조 → 기존 설정 → 프로그램 → 계정/홈 순서다.
재설치는 rollback부터 수행한다. 공유 Python 런타임은 남기고 서버 자격 회수는 기존 콘솔 절차를 유지한다.

## 실패·미완료·한계

- pyflakes 검사 결과가 없다. 구문 검사 성공으로 대체하지 않는다.
- 위키 기본 검사는 ignored 원문 provenance 부재와 코드 매핑 불일치로 처음 실패했다. 매핑은 현재 코드로 재생성하고
  ignored 원문은 저장소의 기존 CI 옵션으로 경고 처리했다. 원문 확보/기존 전체 위협 검토 갱신을 완료했다고 주장하지 않는다.
- pf는 관리 UID의 TCP/UDP 연결에 한정하며 Linux의 모든 IP 프로토콜/AppArmor 격리와 동등하지 않다.
  같은 UID의 헬퍼 직접 호출·관리자 우회는 남는다. PF는 Apple의 안정 API가 아니므로 실제 OS 판본에서 확인해야 한다.
- macOS 실기기, Gatekeeper, dscl 계정, PSF pkg 실행, launchd 재부팅, 실제 모델/MCP 경로와 DB 일회 소비는 미검증이다.
- 외부 자료는 공식 문서·공개 릴리스/카탈로그를 대조했으나 일부 고정 전체 commit·개별 SKILL 원문을 확보하지 못했다.
  외부 스크립트를 실행하거나 새 의존성으로 도입하지 않았다. 자료별 읽기 범위와 라이선스는 분석 문서에 구분했다.
