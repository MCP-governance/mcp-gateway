## 검증 결과

- `PYTHONUTF8=1 python full_stack_lab/tests/run_local_suite.py --out suite.json`: **152파일, 통과 79·실패 54·외부 의존 생략 18·검토 갱신 대기 1**, 종료 1. 원본은 저장소 루트 `suite.json`이다. 파일 통과 수에는 unittest 내부 생략이 포함되므로 승인 시험 전체 성공으로 보지 않는다.
- 지정 `C:/Users/bobysg/suite.json`으로 복사를 시도했으나 파일시스템 권한 거부. 허용된 작업 폴더에 결과를 보존했다.
- 54실패 중 52개는 import/플랫폼 환경 오류: datetime.UTC 19, httpx 7, cryptography 6, tomllib 4, fastapi/psycopg/MCP types/pglast 각 3, re._constants 2, pydantic/grp 각 1. 기본 Python은 3.10. 기존 3.12 가상환경 실행기는 원래 Python 경로에 접근하지 못하며, 그 site-packages의 CPython 3.12 확장도 3.10에서 쓸 수 없다.
- 나머지 `kit_install_upfront_check` 3단언 실패(TOML 확인 subprocess), `user_command_settings_check` Windows winreg 대역 오류는 시작 HEAD의 동일 시험 소스를 별도 subprocess에서 다시 실행해 같은 실패를 확인했다. 이 작업에서 관련 생산 코드·시험을 바꾸지 않았다.
- `threat_trace_mapping_check`: 기존 독립 검토 해시와 현행 소스 불일치로 검토 갱신 대기. 단언·검토 기록을 자동으로 바꾸지 않았다.
- pyflakes: CI와 같은 298파일을 검사. 기존 가상환경의 순수 Python pyflakes를 사용했다. 기본 실행은 Python 3.10에 없는 ExceptionGroup/BaseExceptionGroup 5참조만 실패. `PYFLAKES_BUILTINS=BaseExceptionGroup,ExceptionGroup`으로 Python 3.11+ 내장 이름만 알려 준 보조 검사는 **통과**. 제품에 호환 대역을 넣지 않았다.
- `node --test .github/ci/compose-cache.test.cjs`: **8/8 통과**. 두 JS 구문 검사·`tests/open_endpoints.py`·`git diff --check` 통과.
- 직접 Windows 재현 및 보조 검증: dependency_locks 7, dest_pin 16, field_tls 9, endpoint_stdio 13(+2생략), endpoint_source_api 12, nested_tx_refactor 12, transfer binding AST 4 통과. dest_pin/field_tls 보조 실행만 기존 site-packages의 순수 의존성을 사용했다.

- CI의 Python 3.12와 gateway/requirements.txt 의존성, 비root Linux runner에서 재실행해야 전체 통과 여부를 판단할 수 있다. 특히 승인/출처 증명 시험, Linux 프로세스 정지 시험, 실제 PostgreSQL 회귀는 아직 성공 증거가 없다.
