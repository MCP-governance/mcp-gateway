# 호출 기록과 감사 원장 통합

- 요청: 호출 및 감사 기록의 중복 조회 탭을 합치고 관제 전달 상태를 기록 안에 배치한다.
- 기준: `feat/console-ui`, 시작 커밋 `4ab2caf1`. 기존 미커밋 화면 제목 변경은 보존했다. 커밋과 푸시는 수행하지 않는다.
- 구현: `console.js`의 `ROUTES.activity`, `recordAudit`, `exportCallEvidence`, `showDecision`에서 관리자 탭을 5개로 구성하고 감사 작업과 관제 전달 상태를 호출 기록에 통합했다. 직원 화면은 호출 기록과 분석만 유지한다.
- 조회: `activity.filter_predicates`를 목록, 분석과 감사의 호출 조회 방식에서 공유한다. 사용자 이름, 정확 사용자 ID, 엔드포인트, 부분 정책 ID, 검색어, 추적 ID, 기간과 커서를 보존한다. 감사 API의 기본 원장 조회는 기존 정확 정책 필터를 유지한다.
- 증빙: `audit.PROJECTION`은 변경하지 않았다. 원문 대신 감사 필드를 반환하고 읽기 전용 반복 읽기 트랜잭션에서 전체 원장을 검증한다. 500건 단위의 다음 증빙 내보내기를 제공한다. 감사 관리자 인증과 토큰 기반 직원 본인 범위를 유지한다.
- 오류: 관제 전달 및 사고 조회 실패를 각 영역에 표시한다. 호출 기록 자체는 조회할 수 있다.
- 검증: 관련 UI 5개, `audit_call_filter_check.py` 4개와 `activity_analysis_scope_check.py` 3개, 번역 검사 2개와 JS 및 Python 구문 검사 통과.
- 한계: SQLite 격리 검사이며 실제 PostgreSQL, 솔루션 배포 및 브라우저 검수는 미실행이다. 위키 생성 및 전체 회귀는 실행하지 않았다.
- 결정: [D-311](../../../../docs/ai/decisions/D-301-350.md).
