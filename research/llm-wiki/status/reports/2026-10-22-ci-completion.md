`4022ca7`은 기존 fetch MCP 앞에 CI 전용 Caddy TLS 경로를 두고, 이틀짜리 시험 CA를 기존 공개 루트에 추가한 읽기 전용 번들을 사용한다. 원본 registry와 도구 계약은 보존하고 CI 사본의 fetch endpoint만 바꾼다. 신뢰되지 않은 CA와 잘못된 호스트명은 실제 SSL 오류로 거부된다. Caddy는 생성자 UID/GID로 실행해 leaf key 0600을 유지하며 gateway에는 개인키를 마운트하지 않는다. CA 서명키는 메모리에만 있고 생성 파일은 Git과 증적 업로드에서 제외한다. 실제 Linux Caddy/OSS fetch 및 truststore 동작은 GitHub CI로 판정한다.

`fbd1fc4`는 예약 효과 및 적대 시험을 기존 OAuth MCP 토큰 경로에 맞추고 관리용 Console 세션과 구분한다. 오프라인 회귀 3건은 정상 발급, 전달 경로와 오류 전파를 확인하며 실제 서버 성공의 근거로 쓰지 않는다.

`a151c48`은 main의 검토 원본을 보존한 채 제품 및 관련 시험 6파일의 과거 고유 참조 25개를 독립적으로 재대조하고 새 함수 근거 4개를 연결한다. [독립 변경 검토](../../analysis/threat-trace-review-1022/README.md)는 실제 기기 검증을 주장하지 않는다. Console CLI 추가로 달라진 기업 분석의 현재 코드 참조도 source-only 갱신하고 과거 실행 필드를 보존했다.
