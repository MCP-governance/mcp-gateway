## 찾은 버그와 수정

1. **MCP-EGRESS-002 오판(data: URI)** — `classify.py` `url_destination`(약 행 325~)은 http·https가 아니면 `infrastructure`로 분류한다. `address_arguments`가 `uri`·`url` 값을 모아 넘기므로 markitdown `uri="data:text/html;base64,…"`가 "사내 인프라 주소(SSRF)"로 Block(결정 882·885). 수정: `address_arguments`에서 `data:` 값을 목적지 후보에서 제외(호스트가 없는 인라인 값, 내용은 `dlp_scan`이 계속 본다). 시험 `AddressArguments.test_an_inline_data_uri_names_no_destination` 추가, 기존 기대값 불변. 한계: markitdown은 `uri` 패턴이 허용 호스트 3곳으로 제한돼 있어 수정 뒤에도 `data:`는 PAC-01(범위 밖)로 막힌다. 바뀌는 것은 차단 사유(SSRF 오표시 제거)뿐이다. 게이트웨이 코드라 배포 필요.
2. **재설치 시 만료된 모델 로그인이 "로그인됨"으로 표시** — `bootstrap.py` `harness_login`(행 380~)은 `~/.codex/auth.json` 파일만 있으면 `model_signed_in: true`로 보고하고 로그인 흐름을 건너뛴다. `codex login status`도 파일만 읽어 "Logged in using ChatGPT"를 반환(실측), 서버가 폐기한 토큰은 모든 호출이 401·무한 재연결. 수정: 기존 로그인 재사용을 알리고 재로그인 명령 한 줄을 표시. 엔드포인트 파일이라 기기 `~/mcp-gateway/endpoint-agent`에는 scp하지 않았다(리더 병합 후 `field up`에 포함).

## 수정하지 않고 보고하는 관찰

- 재설치할 때마다 이전 장치 레코드가 `status=active`로 남는다(`endpoint_plane.consume_enrollment`는 같은 소유자·호스트·계정의 이전 장치를 정리하지 않는다). 콘솔 장치 목록에 중복·끊긴 장치가 쌓인다. 이번에 만든 1·2차 PJ1 장치와 Windows 구 장치는 폐기했다. 기존 PJ1 장치 `managed-5a714737`(10-17 사람이 쓰던 것)은 재설치로 로컬이 제거됐으나 레코드는 건드리지 않았다.
- context7 업스트림이 익명 할당량 소진("Monthly quota exceeded")이라 직원에게는 도구가 고장 난 것처럼 보인다. 등록에 API 키가 필요하다(운영 결정).
- markitdown은 응답 262144바이트 상한(MCP-OUTPUT-001, 결정 888)에 큰 페이지(learn.microsoft.com 문서 첫 화면)가 걸린다. 설계된 상한이며 사용자 오류 문구는 "출력 통제"라고만 나온다.
- 허용 호스트 밖 URL은 차단 사유가 `[MCP Gateway · 차단 · PAC-01] 승인된 PAC 실행 범위를 충족하지 못했습니다`로 나와 직원이 원인을 알기 어렵다(결정 887).
- Windows 정상 경로는 조직 IT 선행 승인 배포(`%ProgramFiles%\MCPGatewayInstaller`)와 대상 계정 로그아웃, UAC 승인이 필요해 직원 단독 원클릭이 아니다. 설계 의도(D-68)이나 소유자의 "원클릭" 기준과 간극이 있다.
- Windows `install.cmd`는 모델 로그인 단계가 없다(Linux는 설치 끝에 안내). Windows 첫 실행은 `/login`만 안내된다.
- 활성화 직후 약 1분(정책 반영), 게이트웨이 재배포 중에는 401·502가 한 번씩 나온다.
