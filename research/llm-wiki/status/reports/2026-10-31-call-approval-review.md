# 호출 승인 검토와 목록 보완

- 기준: `feat/console-ui`, 시작 커밋 `56ace776`. 앞선 대시보드 작업의 미커밋 변경을 보존했다.
- 요청: 대기 목록의 30건 제한, 자동 갱신 부재, 상세 확인 없는 즉시 승인과 요청 대상 및 사유 표시를 보완한다.
- 구현: `/approvals`에 페이지와 전체 대기 건수 및 가장 오래된 시각을 추가했다. 만료, 요청 시각, ID 순으로 정렬한다. 요약은 첫 5건이고 전체 탭은 선택한 30건 페이지다. 요청 대상 요약과 사유를 표시하고 하네스는 상세에 둔다.
- 처리: 목록의 실행 및 거부 버튼은 검토 버튼으로 바꿨다. 상세에서 승인과 거부하며 일반 승인에는 실행 최종 확인을 추가했다. 중대 영향의 기존 범위 확인과 증빙 해시 전송을 유지한다. 본인 요청의 승인과 처리 이력의 재실행 버튼은 제공하지 않는다.
- 갱신: 요약과 호출 승인 탭에서 15초 주기로 목록만 갱신한다. 상세 및 확인창, 키보드 포커스가 있는 목록은 보류하며 요청 중 검토를 시작한 경우와 화면을 이동한 경우에도 응답을 적용하지 않는다. 실패 상태는 기존 데이터와 함께 표시하고 복구 시 갱신한다. 마지막 페이지가 비면 유효한 페이지로 보정한다.
- 검증: 관련 JS 검사 11개와 격리 API 검사 3개 통과. 신규 요청 반영, 전체 65건의 마지막 페이지와 독립된 미리보기, 본인 제한과 취소 및 확인, 중대 영향 증빙 해시 전달, 검토 중 갱신 경합, 이전 화면 응답 무시, 오류 복구와 빈 페이지 보정을 검사했다. API 검사는 실제 함수 AST를 분리해 관리자 제한과 페이지 인자 및 전체 메타데이터, 중대 영향 원문 인자 비노출, 조회 실패 전파를 확인했다. JS 및 Python 구문 검사 통과.
- 한계: API 시험은 DB 대역이며 실제 PostgreSQL의 정렬 및 페이징 연동은 미실행이다. 솔루션 배포와 브라우저 검수는 미실행이다. 위키 생성과 전체 회귀는 수행하지 않았다.
- 후속: 실행 PC에서 실제 승인 요청 30건 초과와 만료 및 동시 처리, 자동 갱신, 상세 확인 및 거부, 일반 및 중대 영향 승인 흐름을 검수한다. 커밋과 푸시는 하지 않았다.
