### 수정 및 확인

1. **자동 중지 복귀:** `ops_response.resume()`에서 서버 운영 상태 전환 및 이벤트 기록과 `local_run_stops` 삭제를 같은 트랜잭션에 넣었다. 전환이 실패하면 표식도 남는다.
2. **요청 크기 상한:** `LOCAL_PARAMS_MAX_BYTES` 설정(기본 65,536바이트)을 추가했다. MCP 로컬 도구 인입과 `local_jobs.exchange()`가 직렬화된 인자를 INSERT 전에 검사하며, 초과·직렬화 실패는 `P-RATE-003`으로 차단한다.
3. **저장 결과 해시:** F9 해시를 저장 크기 상한 적용 및 실제 저장할 결과로 계산하도록 순서를 바꿨다.
4. **취소 잠금 순환:** 실행 검증이 DB 트랜잭션·실행 잠금 전에 저장된 `stop_requested`를 잠금 없이 확인하고 즉시 정지한다. 15초 HTTP timeout에 기대지 않는다.
5. **등록 화면 근거:** 화면 조회가 구성값을 `확인 안 됨`과 함께 표시하고, host 모드일 때만 `탈출 시 호스트 root`를 보여준다. 같은 서버·관찰 장치의 최신 `uid_map` 실측을 사용자 매핑 표시로 연결했다. 아직 실측 자료가 없는 경우 확인된 결과로 표시하지 않는다.
6. **낡은 매니페스트 시험:** `local_run_manifest_check.py` fixture에서 `PinnedMounts`와 `mount_options`를 공급하도록 고치고, symlink 및 파일 부재 거부를 직접 검사한다. Windows에서는 Linux 전용 runner 부분을 건너뛴다.

새 고정 시험은 [dev73_review2_check.py](../../../../full_stack_lab/tests/dev73_review2_check.py)다. 다섯 수정 축(복귀 원자성, 상한, 저장값 해시, 잠금 없는 정지 관찰, 구성·uid_map 표시)에 대해 5/5 통과했고, 각 축을 개별 되돌린 변이 확인에서 대응 시험이 실패한 뒤 원복 상태에서 다시 통과했다.

## 실패·미완료·한계

1. F2/F4/F5/F7의 실제 DB·Linux·엔진 증거가 없어 완료 조건의 0건 주장을 입증하지 못했다. 특히 FD bind의 엔진 재해석, userns/idmap의 실제 파일 접근, 정지 실패/재시작 경합은 새 적대 검토 대상이다.
2. 철회/종료 요청은 정지 확인을 기다릴 수 있다. 장치/엔진이 끊기면 전환이 실패/보류되며 미확인 작업을 지워 성공으로 만들지 않는다. 활성 정책 번들뿐 아니라 카탈로그와 capability 문서 hash도 대조하며, 로컬 도구 범위 변경은 정지 후 게시한다. 파일을 직접 교체하거나 새 정책 번들을 배포하는 운영 경로에서도 진행 중 로컬 작업을 먼저 정지해야 한다.
3. 메시지마다 컨테이너를 제거하므로 상태 있는 stdio MCP·세션에 종속된 페이지 cursor 호환성은 미확인이다. 이미지 삭제와 하위 자격/효과 회수는 컨테이너 정지 회신으로 증명되지 않는다. C1~C4/T1~T3 판정 규칙과 기존 `termination_flow.py`는 변경하지 않았다.
4. 이식한 기존 `local_run_manifest_check.py`의 정상 명령 fixture는 새 FD 고정에 필요한 PinnedMounts를 공급하지 않는다. Linux에서 해당 fixture의 조정이 필요할 수 있으나, **기존 기대값·AST는 바꾸지 않았다**. 새 시험과 실제 엔진 근거를 보고 메인이 조정 여부를 판단해야 한다.
5. 실제 Python SDK/암호/DB 의존성 import, 신규 SQL migration, UI 렌더링, 전체 회귀는 미완료다. `status/current.md`와 중앙 위협 매핑은 메인 통합 대상으로 보존했다. 변경 파일/코드 hash는 이 레인의 분석 정본에 기록했다.

## WBS 불일치

이번 확인 범위에서 DEV-73 백로그 완료 조건은 반려 판단 정본과 일치한다. 이전 C10의 로컬 OCI 서명 필수 문구와 1차 구현의 따뜻한 세션/게이트웨이 침해 방어 표현은 이력이며, 이번 적용 범위는 F1/F3 판단과 갱신 설계 §9가 대체한다. 백로그 DEV-73 행에는 이 보고만 연결하고 완료로 올리지 않았다.

### 제품 회귀와 영향 범위

원격 서버에 DB로 보이는 결과 차이는 없었다(원격 서버에는 로컬 작업 행이 없어 확인 루프가 비어 있다). 다만 DEV-73이 원격 서버의 자동 중지·수동 중지·등록 해제·종료 개시·사용자 중지 복귀에 `local_run_stops` 쓰기와 `local_jobs` 조회를 새로 붙였고, `ops_response.resume`은 `local_run_stops` 삭제를 붙였다. 이 테이블이 없거나 느리면 원격 서버의 중지·복귀가 막힌다. 로컬 실행 서버에만 적용하도록 `local_jobs.is_local(server_id)`를 추가해 서버 범위의 `quiesce`·`resume`과 `ops_response.resume`의 삭제를 원격 서버에서는 건너뛴다. 사용자·장치 범위는 서버를 가리지 않으므로 그대로 둔다. 따라서 계정 중지·삭제와 장치 폐기는 로컬 서버가 없는 배치에서도 정지 행을 하나 쓴다. 토큰 철회의 `prepare_token_revocation`도 토큰마다 잠금과 `local_jobs` 쿼리 둘을 더 낸다. 둘 다 결과는 같고 쿼리만 늘며, 토큰 철회는 시작 쪽과 같은 잠금을 쥐어야 하므로 건너뛰지 않았다.

회귀를 고정하는 시험은 `full_stack_lab/tests/dev73_integration_check.py`다. 게이트를 빼면 4건이 깨지는 것을 확인했다.
