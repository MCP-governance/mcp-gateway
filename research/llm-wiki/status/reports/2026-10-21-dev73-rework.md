## 실패·미완료·한계

1. F2/F4/F5/F7의 실제 DB·Linux·엔진 증거가 없어 완료 조건의 0건 주장을 입증하지 못했다. 특히 FD bind의 엔진 재해석, userns/idmap의 실제 파일 접근, 정지 실패/재시작 경합은 새 적대 검토 대상이다.
2. 철회/종료 요청은 정지 확인을 기다릴 수 있다. 장치/엔진이 끊기면 전환이 실패/보류되며 미확인 작업을 지워 성공으로 만들지 않는다. 활성 정책 번들뿐 아니라 카탈로그와 capability 문서 hash도 대조하며, 로컬 도구 범위 변경은 정지 후 게시한다. 파일을 직접 교체하거나 새 정책 번들을 배포하는 운영 경로에서도 진행 중 로컬 작업을 먼저 정지해야 한다.
3. 메시지마다 컨테이너를 제거하므로 상태 있는 stdio MCP·세션에 종속된 페이지 cursor 호환성은 미확인이다. 이미지 삭제와 하위 자격/효과 회수는 컨테이너 정지 회신으로 증명되지 않는다. C1~C4/T1~T3 판정 규칙과 기존 `termination_flow.py`는 변경하지 않았다.
4. 이식한 기존 `local_run_manifest_check.py`의 정상 명령 fixture는 새 FD 고정에 필요한 PinnedMounts를 공급하지 않는다. Linux에서 해당 fixture의 조정이 필요할 수 있으나, **기존 기대값·AST는 바꾸지 않았다**. 새 시험과 실제 엔진 근거를 보고 메인이 조정 여부를 판단해야 한다.
5. 실제 Python SDK/암호/DB 의존성 import, 신규 SQL migration, UI 렌더링, 전체 회귀는 미완료다. `status/current.md`와 중앙 위협 매핑은 메인 통합 대상으로 보존했다. 변경 파일/코드 hash는 이 레인의 분석 정본에 기록했다.

## WBS 불일치

이번 확인 범위에서 DEV-73 백로그 완료 조건은 반려 판단 정본과 일치한다. 이전 C10의 로컬 OCI 서명 필수 문구와 1차 구현의 따뜻한 세션/게이트웨이 침해 방어 표현은 이력이며, 이번 적용 범위는 F1/F3 판단과 갱신 설계 §9가 대체한다. 백로그 DEV-73 행에는 이 보고만 연결하고 완료로 올리지 않았다.

## 다음 작업

메인의 새 적대 검토를 먼저 받는다. 이후 허용된 환경에서 새 PostgreSQL 경쟁/상한/정지 시험, Linux 교체 시험, 지원 엔진·판본의 uid_map/idmap·FD bind·외부 연결 실패·정지/복구를 실제 공개 OSS MCP로 확인한다. 그 검토가 끝나기 전 기기 배포·PJ1 시험으로 진행하지 않는다.
