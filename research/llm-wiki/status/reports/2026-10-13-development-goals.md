# 2026-10-13 개발 목표와 검토 기준

사용자 요청과 기존 설계에서 목표를 도출했습니다. 구현·설정·활성화·실기기 검증·배포 완료는 각각 별도 확인합니다.

## 이번 요청

연구 위키는 Markdown 정본으로 유지합니다. 웹은 Codex와 실제 Claude CLI의 공개 대화·담당 작업·현재 상태·검증을 보는 개발 협업 콘솔입니다. 제품 운영 Console과 개발 협업 화면은 별도입니다.

솔루션 코드를 분석하여 현재 기능·버그·문제·방향성을 확인하고, 조사한 제품과 대조해 목표 기능과 보강안을 정합니다. 실제 Claude Sonnet 5.5 CLI에 `xhigh`를 지정해 검토를 요청하고, 구현 결과를 다시 검토받습니다. 제품에는 메모리·CPU·네트워크 지연 표시를 추가합니다.

## 이번 구현 묶음

1. 위키 웹을 개발 협업 콘솔로 수정하고 실제 Claude CLI 연결 기록을 표시합니다.
2. 현재 코드와 조사 자료를 대조해 재현 가능한 결함·설계 공백·배포 미확인을 나눕니다.
3. CPU·메모리·네트워크 지연 API와 운영 화면을 기존 인증·표시 경계에 추가합니다.
4. field 포트 검사에서 허용 서비스와 주소를 정확히 검증하고, 별도 코드 검토에서 확인한 우선 결함을 수정합니다.
5. 적절한 정적·회귀 검사, 지정 솔루션 기기 배포와 PJ1 실제 하네스 확인을 수행합니다. 불가능한 검증은 미완료로 남깁니다.

## 비교 원칙

[솔루션 분석](../../solutions/README.md)의 고정 커밋·공개 문서를 재사용합니다. 실행 전 PDP·권한 필터·도구 계약·응답 검사·OAuth·호출량 제한 등은 기존 제품도 다룹니다. 신규 서비스나 정책 엔진보다 기존 경로에 적용할 수 있는 작은 보강을 우선합니다. 동일 정상/공격 입력과 독립 upstream 효과를 확인한 비교 실험 전에는 보안 우위를 주장하지 않습니다.

## 시작 상태

WSL Claude Code에 로그인되어 있고 요청한 `claude-sonnet-5-5`의 실제 응답을 확인했습니다. `xhigh`는 CLI 요청 인자이며 서버의 내부 적용을 별도로 증명한 것은 아닙니다.

솔루션 기기와 PJ1은 최초 Tailscale 조회에서 오프라인이었고 SSH는 타임아웃이었습니다. 사용자가 두 기기를 켜고 연결하겠다고 답한 뒤 두 기기의 온라인·SSH·서비스와 PJ1 최신 heartbeat·활성 상태를 확인했습니다. 배포 및 새 실제 하네스 실행은 작업 결과 보고에서 별도로 판정합니다.

실제 Claude 분석 최종 응답은 받았습니다. 수정 후 후속 CLI는 계정 세션 한도로 실패했고 재설정 안내는 당일 17:50 KST입니다. 자동 모델 대체 없이 Codex 구현·검증을 계속하며, Claude 수정 후 재검토는 미완료입니다.
