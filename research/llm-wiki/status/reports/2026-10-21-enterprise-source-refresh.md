# 2026-10-21 기업 분석 CI의 현재 소스 참조 갱신

## 문제와 판단

Research workflow의 `check_enterprise_analysis.py`는 최신 작업 `262f5eb`와 시작 기준 `2045799`에서 동일하게 실패했다. 오류 153개는 요구사항 코드 해시 65개와 통합 코드 해시 88개이며 오류 목록까지 같았다. 이번 제품 변경이 만든 신규 실패와 구분한다. 앞선 작업의 wiki 검사 통과는 이 별도 기업 분석 검사의 통과를 뜻하지 않았다.

요구사항 80행은 `source_only` 60행과 `gap` 20행이고 `test_evidence`가 모두 비어 있다. 통합 조건 50행도 모두 `not_run`이며 실행 근거가 없다. 이 데이터의 `code_evidence`는 현재 소스의 함수와 행을 가리키는 구조 인벤토리다. `build_enterprise_analysis.py`의 기존 계약도 정본 조건과 결과를 보존하며 구조 참조를 갱신한다고 명시한다. 따라서 현재 소스를 다시 관찰해 포인터를 갱신하는 것이 정당하다. 과거 시험 결과나 독립 검토가 새 코드에 유효하다고 바꾸는 작업은 아니다.

## 변경

`build_enterprise_analysis.py --refresh-code-only`는 요구사항과 통합 조건의 현재 `code_evidence` 및 통합 표시문자열 `our_code_evidence`만 갱신한다. 각 근거의 `source_commit`과 별도 `code_observation`에 관찰한 커밋 `9e51e0f36865ce0dd87a6fab8f3fcf6533339522`를 기록했다. 과거 `metadata.head`, `analysis_base_commit`, `checked_at`, 조건, 상태, 시험 해시, 실행 결과와 미지의 추가 필드는 보존한다. 미커밋 참조 소스, 없는 심볼 또는 모호한 통합 anchor는 거부하고 입력 데이터가 읽는 사이 바뀌면 덮어쓰지 않는다.

기존 전체 재생성 경로는 사용하지 않았다. 해당 경로는 시험 근거의 해시까지 현재 값으로 갱신할 수 있고 통합 생성기는 과거 분석 날짜와 서술을 다시 적용할 수 있기 때문이다. 새 모드는 구조 참조만 다룬다. 과거 독립 검토 파일과 실행 로그는 변경하지 않았으며 사용자 검수나 실기기 상태도 승격하지 않았다.

## 검증

- 현재 구조 참조만 메모리에서 바꾼 선행 재현: 검사 153오류에서 0오류로 전환, 파일 변경 없음.
- 실제 갱신 후 요구사항 80행과 통합 50행의 모든 비소스 필드를 Git 원본과 비교: 모두 동일. 과거 메타데이터도 동일.
- 새 회귀 3건: 합성 `verified_unit`/`passed` 데이터의 과거 시험 해시와 실행 기록 보존, 모호한 anchor의 무변경 거부, 미커밋 소스의 무변경 거부. 모두 통과.
- 기업 분석 검사: 오류 0, 경고 0. 변경 도구 pyflakes와 diff 공백 검사 통과.
- Research workflow에 새 회귀 실행을 추가했다. 로컬 검사는 원격 Actions 성공을 뜻하지 않으며 push 뒤 실행 결과는 별도로 확인해야 한다.

현재 소스 구조 관찰을 갱신했을 뿐 요구사항 구현 완료나 실행 성공을 새로 주장하지 않는다. 최신 시트 57행의 진척과 별도 독립 검토 해시 실패를 변경하지 않는다.
