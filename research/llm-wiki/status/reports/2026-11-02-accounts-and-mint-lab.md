# 2026-11-02 비밀번호·아이디 관리와 실습 회사 이름 mint

- 작업자: Claude Code
- 코드 기준: main `df46b0d0`(v1.0.0) → 브랜치 `11/02-accounts-mint`(PR #81)
- 시작 근거: 소유자 지시(11-02) 「실습 회사 값 bob.local 같은 것을 mint로, root 비밀번호 변경 기능, admin1·2 계정명·비밀번호 변경 기능」
- 해결할 문제와 완료 조건: 콘솔에서 root를 포함한 모든 계정이 자기 비밀번호를 바꾸고, root가 관리자 계정의 아이디·비밀번호를 바꾼다. 실습 회사 값이 mint로 일관된다.

## 결과

- `POST /auth/password`(콘솔 상단 열쇠 버튼): 현재 비밀번호 확인 후 변경, 로그인과 같은 시도 제한, 이 세션은 남기고 다른 콘솔 세션 종료.
- `PUT /api/accounts/{id}/password`·`PUT /api/accounts/{id}/name`(사용자 관리 행 메뉴 「비밀번호 재설정」·「아이디 변경」):
  관리자 계정은 root만, 자기 계정은 이 메뉴로 못 바꿈. 관리자 비밀번호는 `./mint.sh set-password`와 같은 12자 이상, 직원은 가입 규칙(8자).
  변경 뒤 그 계정의 콘솔 세션·발급 토큰·연동 세션을 끝낸다. 아이디 변경은 principal(token)을 그대로 두어 기록이 이어지고,
  로그인 주소가 아이디였던 계정은 로그인 주소·표시 이름도 따라간다. 현장 모드에서는 Gitea 사용자 이름도 바꾼다(`/api/v1/admin/users/{name}/rename`).
  `principals.password_changed_by·_at`을 더했다.
- 실습 회사 이름·도메인 `bob`·`bob.local` → `mint`·`mint.local`(82개 파일, 실습 PC 도구 `mint-ask`·`mint-sso`, `workstation/managed/mint`).
  결정 기록·연구 위키·변경 기록의 과거 항목은 그대로.

## 실패·미완료·한계

- 콘솔에서 root 비밀번호를 바꾸면 서버의 `initial-admin-password` 파일은 남는다(컨테이너가 배포 폴더를 쓰지 않음). 운영 안내에 직접 지우라고 적었다.
- 실습 데이터로 시작한 다른 배치는 이전 `@bob.local` 계정이 현장 모드 목록에 보일 수 있다(도메인 이전 SQL 필요). 메인 :443 스택은 아직 이전 판본.
