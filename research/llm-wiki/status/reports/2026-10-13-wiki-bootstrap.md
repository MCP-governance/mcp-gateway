## 검증

자료 원본의 SHA-256과 복사본을 대조하고 전체 추출 MD의 UTF-8, 출처·판본·로컬 링크·원본 존재를 검사했습니다. 코드 증거 manifest의 21개 해시를 확인했습니다. 위협 XLSM은 복사 전후 해시가 일치하고 매크로 실행·원본 수정·재계산을 하지 않았습니다.

정적 웹은 HTTP 200과 브라우저 검색·분류·문서 간 이동·표 렌더링·390px 모바일 배치를 확인했습니다. 가로 넘침은 없었습니다. 원문 HTML과 악성 Markdown을 활성 스크립트로 렌더링하지 않는 self-check, 생성 웹과 정본 MD·JSON 동기화, 원본·위협표·코드 후보 해시·로컬 링크 검사가 통과했습니다. 자동 검사 결과는 [validation](../validation.json)에 보존합니다.

서버 없이 동작하도록 본문을 로컬 JS에 포함하고 외부 fetch/CDN 의존성을 없앴습니다. 자동 브라우저 도구는 보안 정책상 `file:` URL을 허용하지 않아 파일 직접 열기 검수는 수행하지 못했고 HTTP 경로에서 검수했습니다.

Git에는 위키·진입점·위키 검사 workflow만 반영합니다. 시작 시 존재한 엔드포인트·오염 검사·docs/ai 미커밋 변경은 위키 커밋에서 제외합니다. 위협 추적 JSON은 이들 파일의 로컬 hash와 HEAD hash를 분리합니다.

## 정정한 근거

ContextForge의 검토 커밋에서 PII 플러그인은 `enforce`입니다. 기존 “모두 disabled” 설명을 새 코드 분석에서 정정했습니다. LiteLLM은 확보한 커밋·해당 버전의 소스로 확인했습니다. 계약 변경은 발견 시점에 따라 `MCP-CATALOG-001` 또는 dispatch 경로의 `P-CONTROL-FAIL-CLOSED`로 기록되므로 실험 기대값을 구분했습니다.

## 한계와 다음 작업

논문 전체 정독·모든 표와 그림 육안 검사·논문 재현·상용 trial·솔루션 배포·원격 MCP 연결·PJ1 실제 하네스 실험은 수행하지 않았습니다. 과거 검증 기록은 새 결과로 합산하지 않습니다. 모든 실험 카드는 `not_run`, 실제 결과는 null입니다.

현황 갱신은 Claude/Codex의 작업 종료 규칙으로 연결했습니다. 무인 주기 실행을 따로 설정한 것은 아닙니다. 웹은 MD에서 생성하는 읽기 화면입니다.

## 사용자에게 필요한 입력

위키 구축에는 추가 입력이 필요하지 않았습니다. 다른 최신 위협표가 있으면 파일 경로를 알려 주면 됩니다. 실기기 실험으로 넘어갈 때 시험할 MCP 우선순위와 최소 권한의 테스트 계정·자격을 운영자 경로로 준비합니다.
