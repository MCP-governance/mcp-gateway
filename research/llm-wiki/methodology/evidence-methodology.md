# 실제 MCP와 최신 연구를 이용한 검증 방법

[논문 재검토 정본](../analysis/reference-updates.json)은 정식 저널3건, AAAI 학회1건, 게재처 미확인 preprint1건을 분리한다. ACM TOSEM·IEEE TSE·Information Sciences의 서지/선별 본문 근거를 확인했고 일부 전문은 publisher 접근 제한으로 읽지 못했다. IF 수치는 검증하지 않아 넣지 않는다. 정식 게재·최신 날짜만으로 제품 보안을 인정하지 않는다.

MCPTox의 정상 업무·trigger·행위·정당화 구분은 시험 입력을 설계하는 데 사용한다. 이 프로젝트는 **자체 MCP를 만들지 않고** 공식 GitHub MCP의 toolset/description override와 이미 공개된 실제 OSS 도구·자기 소유 합성 자원만 사용한다. 판본 고정·독립 승인·격리 관계를 전제로 설명 변화와 실제 후속 실행 효과를 구분한다.

## 케이스의 최소 데이터

각 케이스에는 요구사항/위협/실험 ID, 제품·SDK·MCP·정책·schema·데이터·모델·하네스 판본, 조건 분류(정상/음성/경계/장애/경쟁/복구), principal/device 상태, 입력·예상 policy_id·효과·원복, 실제 IDs·시각·원본 hash·증거 수준을 남긴다. source/metadata/단위/프로토콜/실제 자연어/독립 효과를 별도 상태로 둔다.

동일 케이스의 정상군과 공격군은 업무·권한·자원·schema·모델을 일치시킨다. 비교 제품도 해당 edition과 enforce 활성 구성을 기록한다. 한 제품은 PII masking, 다른 제품은 blocking이면 같은 결과 척도라고 가정하지 않는다. Alert+실행을 Block으로 집계하지 않는다.

## 측정과 판정

- 정상 완료율, 정상군의 오탐, 공격군의 미탐, 실제 비승인 효과 발생률, 정확한 정책 차단률을 분리한다. 모델의 거절 문구나 인자 생성만으로 공격 성공/실패를 판정하지 않는다.
- Gateway attempted/executed와 공급자 접속 로그·메일 수신·Gitea 새 issue 등 독립 효과를 연결한다. 멱등 덮어쓰기/중복 제거가 효과1을 만들었다고 실행1로 추정하지 않는다.
- 모델·동시성·입력 길이·seed·반복 횟수·성공/실패/미확인 분모를 보존한다. 미확인을 조용히 제외해 성공률을 높이지 않는다.
- 규칙 개발에 사용한 출처·공격 템플릿·근접 중복이 평가군으로 새지 않도록 출처/공격 계열 단위로 분리한다. 같은 출처에서 문자열 hash로 나눈 held-out은 새 출처 일반화 증거와 다르다. 독립 한국어 업무 문서·공격군과 실제 하네스의 비승인 효과를 [DEV-46 검토](../analysis/review-2026-10-15/README.md)에 연결한다.
- 비율은 적절한 구간 추정과 원자료 개수를 함께 보고한다. 후속 분석은 검증된 scipy 통계 API를 우선하며 맞춤 통계 엔진을 만들지 않는다. 반복 횟수/성능 예산은 업무 목표와 pilot 결과로 확정한다.
- 지연 p50/p95, Gateway 추가 지연, CPU/메모리·오류율·효과 수는 고정 workload에서 측정한다. 현재 단일 내부 TCP 표본을 기업 지연 목표 충족으로 쓰지 않는다.
- 테스트 대상 MCP는 실제 상용/OSS만. OPA/network 장애는 Toxiproxy 등 기존 OSS로 전용 경로에 주입한다. 기존 내부 단위 대역은 실행 증거로 올리지 않는다.

원복은 만든 자원만 finally로 정리하며 공유 계정/계약/원장/업무 관계를 초기화하지 않는다. 공개 보고서는 비밀 제거 projection·원본 hash·검증 범위·반례·제약을 포함한다. 원본 전문 재배포 조건을 확인하고 CC-BY-ND/IEEE/AAAI 전문을 임의 번역·공개하지 않는다.
