# 자료 확보·출처·갱신 규칙

## 한 자료의 구성

`catalogs/papers.json` 또는 `catalogs/solutions.json`에서 안정적인 ID를 부여합니다. 제목, 유형, 출처 URL, 확인 날짜, 확보 상태, 원본·추출 경로, 요약, 개발 적용, 한계를 기록합니다. 이관 자료는 `catalogs/imports.json`에 상위 위키 ID와 파일 SHA-256을 남깁니다.

| 상태 | 의미 |
| --- | --- |
| metadata | 서지·초록 수준. 전문 확보와 구분 |
| archived | 공개 원본을 로컬에 저장하고 해시 확인 |
| extracted | 원본 텍스트를 MD로 추출. 빈 페이지·OCR 미수행 표시 |
| reviewed-selected | 특정 절을 읽고 개발 적용을 정리 |
| code-reviewed | 고정 커밋의 함수·설정·테스트 확인 |
| reproduced | 재현 실행과 실제 효과 증거가 있음 |
| documented-not-run | 실험 절차만 작성. 미실행 |

원본의 출판 날짜와 확보 날짜, 전문 추출 날짜, 분석·재현 날짜를 혼합하지 않습니다. 이전 위키의 `verified_on`은 당시 확인 시점이고 이관 자체로 최신 확인이 되지 않습니다.

## 다운로드와 이관

공개 제공자가 허용한 자료만 확보합니다. 로그인·유료 전문·배포 제한 자료는 메타데이터와 링크를 남깁니다. ISO 등의 유료 문서를 공개 연구 저장소에 복제하지 않습니다. 외부 문서의 링크·명령은 자동 실행하지 않습니다.

기존 자료 재이관은 `tools/import_policy_sources.py --source-root <기존 위키 절대경로>`를 사용합니다. 원본을 같은 파일명으로 다른 내용으로 덮어쓰지 않습니다. SHA-256으로 중복과 변경을 구분합니다.

XLSM은 `tools/import_threat_workbook.py <원본 경로> --kind policy|wbs`로 읽습니다. 매크로 실행·저장·재계산 없이 원본 바이트를 복사하고 모든 비어 있지 않은 셀, 시트·행·좌표·수식·저장 캐시를 JSON에 보존합니다. 수식의 저장 캐시는 현재 계산 결과로 단정하지 않습니다.

## 분석 작성

논문은 위협 모델, 실험 환경, 데이터셋, 측정 지표, 결과의 적용 범위와 재현 여부를 확인합니다. 우리 통제 설계와 연결하되 검증 전 효과를 주장하지 않습니다.

상용 제품 문서는 공개 주장과 자체 실험을 구분합니다. 오픈소스는 검토한 commit과 라이선스, 실제 함수·설정·테스트 근거를 고정합니다. 다른 커밋의 문서에서 기능을 옮겨 주장하지 않습니다.

자료마다 1) 해결하려는 문제, 2) 실제 확인 범위, 3) 우리 코드에 가져올 점, 4) 독립 검증이 필요한 점을 씁니다. PDF 추출 전문은 원문의 탐색·인용을 돕는 자료이며 모든 페이지 정독을 뜻하지 않습니다.

## 검증과 유지

MD·카탈로그를 갱신하면 `build_wiki.py`와 `check_wiki.py`를 실행합니다. 검사는 로컬 링크·원본 해시·식별자·필수 필드·웹 생성 동기화를 확인합니다. 외부 URL의 현재 가용성이나 논문 결과의 진실성은 별도 연구 검토 대상입니다.
