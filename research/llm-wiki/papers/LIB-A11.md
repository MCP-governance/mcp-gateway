# LIB-A11 · SEP-2322: Multi Round-Trip Requests

서버 발신 요청(예: 도구 호출 중의 elicitation)을 클라이언트 요청의 재시도 흐름인 multi round-trip으로 처리하도록 바꾸는 SEP다. 공유 스토리지나 연결 상태 없이 여러 서버 인스턴스에서 동작하도록 하는 것이 목표다.

## 출처와 확인 수준

- 공식 출처: [SEP-2322: Multi Round-Trip Requests](https://modelcontextprotocol.io/seps/2322)
- 유형: 명세·제안 · 2026년 · MCP SEP (Final, Standards Track) · `mcp_sep`
- 저자·발행: Mark D. Roth, Caitie McCaffrey, Gabriel Zimmerman
- 확인일: 2026-10-14 / `page_title_matched` — 제목을 공식 페이지와 대조했다.
- 요약 검토: 출처 페이지와 수치·용어를 대조하고 의심 문장은 원문으로 확인했다.
- 배포: `public-under-license` — 서지와 자체 요약만 보관하고 원문은 복제하지 않는다.

## 읽은 내용

- 서버 발신 요청을 공유 스토리지 없이 처리해 로드밸런싱 환경에서의 상태 의존을 줄이는 것이 목적이다.
- SSE 스트림 의존을 낮춰 장시간 연결을 유지하기 어려운 환경도 지원하도록 한다.
- 기존 서버 발신 요청 방식을 대체하며, 이는 breaking change로 명시되어 있다.

## 우리 솔루션 개발에 사용할 곳

- 게이트웨이가 서버 발신 요청을 중계할 때 공유 저장소 없이 재시도 사이의 상태를 운반하는 구조가 MRTR의 전제이므로, 게이트웨이의 다중 인스턴스 설계를 이 방식 기준으로 검토한다.
- 요청 사이에 왕복하는 상태를 게이트웨이가 변조 가능한 입력으로 보고 무결성을 검증할지 정책으로 정한다(추론이며, 본문의 requestState 세부는 확인하지 못했다).
- 기존 방식을 대체하는 호환성 깨짐 변경이므로 게이트웨이의 프로토콜 버전별 어댑터 계획에 포함한다.

적용 항목은 개발 후보이며 우리 구현이나 배포에서 검증된 기능이 아니다.

## 한계와 사용 조건

SEP 앞부분(초록과 서두)만 확인했고, 상세 메커니즘과 requestState 형식은 정독하지 않았다. 2026-07-28 개정에 실제로 반영된 형태는 2차 자료 기준이라 미검증이다. 요약 초안은 조사 에이전트가 작성했고 위 검토 수준까지 확인했다. 발행처 표기는 확인하지 않았다.

라이선스 미확인: 본문을 복제하지 않고 서지·자체 요약만 보관한다.
