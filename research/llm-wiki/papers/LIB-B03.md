# LIB-B03 · Prompt Injection Attack to Tool Selection in LLM Agents

에이전트의 도구 라이브러리에 악성 도구 문서 하나를 끼워 넣어, 모델이 공격자가 정한 작업마다 그 도구를 계속 고르게 만드는 프롬프트 인젝션 기법 ToolHijacker를 제안한다. 검색 단계와 선택 단계를 나눠 최적화하며, 시험한 예방형·탐지형 방어가 충분하지 않다고 주장한다.

## 읽은 내용

- 도구 문서 하나만 조작해도 특정 작업에서 도구 선택을 공격자가 원하는 쪽으로 유도할 수 있다고 보고한다.
- 예방형(StruQ, SecAlign)과 탐지형 방어 모두 불충분하다고 결론 내린다.
- 공격 문서를 검색 단계용 부분과 선택 단계용 부분으로 나눠 최적화하는 2단계 방식을 제시한다.

## 우리 솔루션 개발에 사용할 곳

- 게이트웨이 도구 카탈로그에 등록되는 설명 문서를 검색과 선택 전에 정적으로 점검해, 지시형 문구나 '항상 이 도구를 쓰라'류 문장을 차단하거나 표시한다.
- 도구 선택 빈도 이상을 탐지 신호로 감사 원장에 남긴다. 특정 도구가 비정상적으로 자주 선택되면 승인 큐로 보낸다.
- 프롬프트 수준 방어에 기대지 않고, 고위험 도구 호출은 OPA 정책과 승인 단계에서 판정하도록 설계한다. 논문이 탐지 기반 방어의 한계를 보였기 때문이다.

적용 항목은 개발 후보이며 우리 구현이나 배포에서 검증된 기능이 아니다.
