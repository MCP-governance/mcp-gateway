# LIB-D10 · Towards Verifiably Safe Tool Use for LLM Agents

STPA(시스템 이론 기반 위험 분석)로 에이전트 워크플로의 위험을 찾고, 도출한 안전 요구사항을 데이터 흐름과 도구 호출 순서에 대한 집행 가능한 명세로 바꾸는 방법을 제안한다. 아울러 기능(capability), 기밀성, 신뢰 수준 라벨을 붙인 MCP 프레임워크를 제시한다.

## 출처와 확인 수준

- 공식 출처: [Towards Verifiably Safe Tool Use for LLM Agents](https://arxiv.org/abs/2601.08012)
- 유형: 논문 · 2026년 · ICSE NIER 2026 · `preprint`
- 저자·발행: Aarya Doshi, Yining Hong, Congying Xu, Eunsuk Kang 외
- 확인일: 2026-10-14 / `arxiv_abs_title_matched` — 제목·저자·최초 게시 연도를 공식 페이지와 대조했다.
- 요약 검토: 초록과 문장 단위로 대조했다.
- 배포: `public-under-license` — 서지와 자체 요약만 보관하고 원문은 복제하지 않는다.

## 읽은 내용

- 모델 기반 판정기와 패턴 필터는 일부 문제를 잡을 수 있으나 보장을 주지 못한다고 주장한다. 이것이 결정론적 모니터가 필요하다는 근거로 제시된다(초록).
- 안전 요구사항을 집행 가능한 명세로 바꾸어 형식적 보장을 지향한다고 밝힌다(초록). 정량 평가는 초록에 없다.

## 우리 솔루션 개발에 사용할 곳

- 게이트웨이 정책을 만들기 전에 위험 분석 단계를 둔다. 도구별로 유출과 오작동이라는 손실 상황을 먼저 적고, 이를 정책 규칙으로 번역하는 절차를 정책 작성 가이드에 넣는다.
- 기능, 기밀성, 신뢰 수준 라벨을 MCP 도구 메타데이터 스키마에 포함하는 방안을 검토한다.
- 정책이 데이터 흐름과 도구 순서를 함께 명세한다는 점을 참고해, OPA 정책 테스트에 호출 순서 시나리오를 추가한다.

적용 항목은 개발 후보이며 우리 구현이나 배포에서 검증된 기능이 아니다.

## 한계와 사용 조건

초록과 키워드만 확인했고 전문은 정독하지 못했다. 적용 사례의 규모와 사용한 형식 검증 도구는 확인하지 못했다. 정량 결과가 초록에 없어 효과에 대한 근거는 약하다. 요약 초안은 조사 에이전트가 작성했고 위 검토 수준까지 확인했다. 발행처 표기는 확인하지 않았다.

라이선스 미확인: 본문을 복제하지 않고 서지·자체 요약만 보관한다.
