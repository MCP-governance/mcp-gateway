# LIB-G13 · A Measurement Study of Model Context Protocol Ecosystem

여섯 개 마켓플레이스에서 14일간 수집한 MCP 프로젝트 17,630건 중 유효한 8,401건(서버 8,060, 클라이언트 341)을 분석한 최초의 대규모 생태계 측정 연구다. 등록된 프로젝트의 절반 이상이 무효이거나 가치가 낮고, 서버 생태계에는 의존성 집중과 불균등한 유지보수라는 구조적 위험이 있다고 주장한다.

## 읽은 내용

- 17,630건 중 8,401건만 유효했고, 등록된 프로젝트의 절반 이상이 무효이거나 가치가 낮다고 보고한다.
- 서버 생태계에는 의존성 집중과 불균등한 유지보수라는 구조적 위험이 있다.
- 클라이언트는 프로토콜과 연결 방식이 아직 과도기 단계에 있다고 결론짓는다.

## 정독 메모

읽은 범위: 초록, 서론, RQ별 요약 결과, 서버 유지보수·클라이언트 프로토콜 분석, 한계

- MCPCrawler로 6개 마켓을 14일간 수집해 17,630건 중 8,401건(서버 8,060·클라이언트 341)을 분석했다. 서버 항목 16,950건 중 8,635건이 무효·저가치로 걸러졌고, 500건 표본 수동 검증에서 무효 판정 정확도는 93.5%였다.
- 서버의 40.9%는 최근 90일 안에 갱신됐고 21.9%는 1년 넘게 갱신이 없다. 11.2%는 민감 API를 호출할 수 있는 코드를 포함하며 그중 43%가 인증 관련 서비스다. Java 서버는 Spring, Python·TypeScript는 pydantic·zod에 의존이 쏠린다.
- 클라이언트는 SSE 56.9%, stdio 38.1%이며 80.9%가 단일 서버 연결만 지원한다. 저자는 Streamable HTTP 채택이 27.9%로 느리다고 적는다.
- 한계: 14일 스냅숏이며 저장소 메타데이터·선언 의존성에 기반하므로 런타임 동작은 보지 못했다.

## 우리 솔루션 개발에 사용할 곳

- 서버 허용 목록 심사에 유지보수 상태, 포크 여부, 방치 여부를 반영해 레지스트리 항목의 신뢰도를 점수화한다.
- 클라이언트가 전송 방식과 연결 패턴에서 과도기에 있다는 점을 고려해, 게이트웨이의 전송 계층을 여러 방식과 호환되게 설계한다.
- 같은 저장소의 서버 분포를 테스트 픽스처로 쓰는 방법을 MCPCorpus와 함께 검토한다.
- 등록·승인 대상 서버를 고를 때 갱신 이력·의존성 집중도·민감 API 호출 여부를 심사 항목에 넣는 근거로 쓴다(설계 제안).

적용 항목은 개발 후보이며 우리 구현이나 배포에서 검증된 기능이 아니다.

## 한계와 사용 조건

WebFetch로 확인한 초록 수치만 반영했다. 14일 크롤링 기반의 시점 스냅샷이다. 전문은 미정독이며 세부 분포 수치는 확인하지 못했다. 2025년 9월 제출, 2025년 11월 개정 자료다. 2026-10-14에 arXiv PDF의 초록, 서론, RQ별 요약 결과, 서버 유지보수·클라이언트 프로토콜 분석, 한계을 읽고 확인했다(PDF는 위키에 보관하지 않고 SHA-256만 기록). 전문 전체 정독·재현은 하지 않았다. 요약 초안은 조사 에이전트가 작성했고 위 검토 수준까지 확인했다. 발행처 표기는 확인하지 않았다.
