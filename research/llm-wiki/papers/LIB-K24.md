# LIB-K24 · CISA: Minimum Requirements for Vulnerability Exploitability eXchange (VEX)

VEX 문서를 만들 때 필요한 최소 요소를 규정하는 CISA 문서의 소개 페이지다. VEX는 제품이 특정 취약점의 영향을 받는지에 대한 공급자 진술을 기계 판독 형태로 전하는 방식이다.

## 출처와 확인 수준

- 공식 출처: [CISA: Minimum Requirements for Vulnerability Exploitability eXchange (VEX)](https://www.cisa.gov/resources-tools/resources/minimum-requirements-vulnerability-exploitability-exchange-vex)
- 유형: 지침 · 2023년 · CISA 간행물, 게시일 2023-04-21 · `official_publication`
- 저자·발행: CISA (VEX 작업반 조율)
- 판본: 게시일 2023-04-21(페이지 표시). 문서 본문 PDF는 열지 않았다
- 확인일: 2026-10-17 / `page_metadata_checked` — 랜딩 페이지의 제목·판·날짜·초록만 확인했다(본문 미정독). 읽은 범위: 랜딩 페이지의 제목·게시일·요약 문장만.
- 요약 검토: 페이지 메타데이터만 확인했다(본문 미정독).
- 배포: `public-under-license` — 서지와 자체 요약만 보관하고 원문은 복제하지 않는다.

## 읽은 내용

- 페이지는 이 문서가 VEX 문서를 만들기 위한 최소 요소를 명시한다고 소개하고 게시일을 2023-04-21로 표시한다.
- OpenVEX 명세가 이 최소 요건 문서를 준수한다고 명시해 상호 참조가 확인된다(LIB-K23).

## 우리 솔루션 개발에 사용할 곳

- **POL-39**: VEX를 도입할 때 문서에 반드시 들어가야 할 최소 필드를 정하는 기준으로 삼는다. 구체 필드 목록은 문서 본문을 읽은 뒤에 확정한다.

적용 항목은 개발 후보이며 우리 구현이나 배포에서 검증된 기능이 아니다. 이 자료를 읽었다는 사실이 해당 정책의 구현·검수 완료를 뜻하지 않는다.

## 한계와 사용 조건

랜딩 페이지의 제목·게시일·요약만 확인했다. 최소 요건의 구체 항목은 읽지 않았으므로 설계에 인용하지 않는다.

페이지에서 별도 이용 조건을 읽지 못했다. 본문을 복제하지 않고 서지·자체 요약만 보관한다.
