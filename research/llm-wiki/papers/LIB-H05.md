# LIB-H05 · Secret Breach Detection in Source Code with Large Language Models

정규식과 엔트로피 기반 비밀 탐지 도구가 맥락을 몰라 오탐이 많다는 문제의식에서 출발해, 정규식으로 후보를 뽑은 뒤 LLM이 실제 비밀정보인지 분류하는 방식을 제안한다. 818개 GitHub 저장소 벤치마크에서 소형 LLM을 미세조정해 비교했다고 보고한다.

## 출처와 확인 수준

- 공식 출처: [Secret Breach Detection in Source Code with Large Language Models](https://arxiv.org/abs/2504.18784)
- 유형: 논문 · 2025년 · ESEM 2025 · `preprint`
- 저자·발행: Md Nafiu Rahman, Sadif Ahmed, Zahin Wahab, S M Sohan 외
- 확인일: 2026-10-14 / `arxiv_abs_title_matched` — 제목·저자·최초 게시 연도를 공식 페이지와 대조했다.
- 요약 검토: 초록과 문장 단위로 대조했다.
- 배포: `public-under-license` — 서지와 자체 요약만 보관하고 원문은 복제하지 않는다.

## 읽은 내용

- 초록 기준, 정규식과 엔트로피 도구는 맥락 정보가 없어 오탐이 많다는 문제를 제시한다.
- 초록 기준, 정규식 후보와 LLM 분류를 결합하는 방식이 정규식 단독 기준선보다 낫다고 보고한다.
- 초록 요약 기준, 이분류에서는 미세조정한 LLaMA-3.1 8B가 가장 높은 F1을 기록했다고 보고한다.

## 우리 솔루션 개발에 사용할 곳

- 게이트웨이 비밀정보 탐지를 2단계로 구성한다. 1단계 정규식 후보 추출은 게이트웨이 안에서 빠르게 수행하고, 후보만 사내에서 돌리는 소형 LLM에 넘겨 오탐을 줄인다. 원문을 외부로 보내지 않는다는 조건을 함께 건다.
- 분류 결과는 정책 엔진의 입력(차단, 마스킹, 승인)으로 쓰되, LLM 판정이 실패하면 정규식 결과로 fail-closed 처리한다.
- 미세조정 학습 데이터를 만들 때 사내 샘플의 오탐 사례를 모아 라벨링 기준을 문서화한다.

적용 항목은 개발 후보이며 우리 구현이나 배포에서 검증된 기능이 아니다.
