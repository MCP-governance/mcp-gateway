# LIB-A08 · SEP-1024: MCP Client Security Requirements for Local Server Installation

원클릭으로 로컬 MCP 서버를 설치하는 흐름에서 클라이언트가 명령을 실행하기 전에 명시적 사용자 동의와 명령 전체 공개를 요구하는 보안 요구사항을 정의한다. 링크나 소셜 엔지니어링으로 임의 명령이 실행되는 것을 막는 것이 목적이다.

## 출처와 확인 수준

- 공식 출처: [SEP-1024: MCP Client Security Requirements for Local Server Installation](https://modelcontextprotocol.io/seps/1024)
- 유형: 명세·제안 · 2025년 · MCP SEP (Final, Standards Track) · `mcp_sep`
- 저자·발행: Den Delimarsky
- 확인일: 2026-10-14 / `page_title_matched` — 제목을 공식 페이지와 대조했다.
- 요약 검토: 출처 페이지와 수치·용어를 대조하고 의심 문장은 원문으로 확인했다.
- 배포: `public-under-license` — 서지와 자체 요약만 보관하고 원문은 복제하지 않는다.

## 읽은 내용

- MUST 요구사항으로 설치 전 동의 대화상자에 명령과 인자를 잘림 없이 표시하고, 명시적 승인과 취소 옵션을 제공해야 한다.
- 승인이 없거나 거부되면 설치를 진행하지 않아야 한다.
- SEP는 사용자 오승인과 난독화 등 잔여 위험을 스스로 인정하고 샌드박스·서명 같은 추가 계층을 권장한다.

## 우리 솔루션 개발에 사용할 곳

- 게이트웨이의 MCP 서버 등록 흐름에서 stdio 명령과 인자 전체를 잘라내지 않고 보여준 뒤 명시적 승인을 받은 경우에만 실행한다. 승인 기록에는 명령의 해시를 함께 남긴다.
- 정책 엔진(OPA)에 로컬 서버 실행 명령의 허용 목록을 두고, 신뢰되지 않은 출처의 설정이 자동 실행되지 않도록 규칙을 쓴다.
- SEP가 인정한 잔여 위험(사용자 오승인, 난독화된 명령, 구현 오류)을 근거로 샌드박스나 서명 검증 같은 추가 계층을 게이트웨이 로드맵에 넣는다.

적용 항목은 개발 후보이며 우리 구현이나 배포에서 검증된 기능이 아니다.

## 한계와 사용 조건

SEP 본문 전체를 확인했다. Final 상태이나 '역사적 기록'으로 표시되어 있어 현행 스펙과의 차이는 확인하지 않았다. 요약 초안은 조사 에이전트가 작성했고 위 검토 수준까지 확인했다. 발행처 표기는 확인하지 않았다.

라이선스 미확인: 본문을 복제하지 않고 서지·자체 요약만 보관한다.
