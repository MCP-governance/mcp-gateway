# LIB-C02 · Defeating Prompt Injections by Design

신뢰된 사용자 질의에서 제어 흐름과 데이터 흐름을 추출하고, 신뢰되지 않은 검색 데이터가 프로그램 흐름을 바꾸지 못하도록 격리하는 보호 계층 CaMeL을 제안한다. 또한 도구 호출 시점에 검사되는 권한(capability)으로 민감 데이터가 허가되지 않은 흐름으로 나가는 것을 막는다고 주장한다.

- 요약 검토: 초록과 문장 단위로 대조했다.

## 읽은 내용

- AgentDojo 과제 중 상당수를 증명 가능한 보안 하에 해결했다고 보고하며, 방어가 없는 시스템과 비교해 일부 과제 성공률이 줄어드는 유틸리티 비용이 있음을 밝힌다.
- 보안 보장은 모델의 강인성이 아니라 제어·데이터 흐름 분리와 도구 호출 시점의 권한 검사에서 나온다고 주장한다.

## 우리 솔루션 개발에 사용할 곳

- 게이트웨이에서 출처 태깅을 도입한다. 각 도구 응답에 출처와 신뢰 등급을 붙이고, OPA 정책이 그 태그를 보고 후속 도구 호출을 허용하거나 차단하게 한다.
- PII 마스킹과 연결한다. 민감 값에 권한을 부여해 외부 전송 도구 호출 시점에 흐름을 검사하면, 마스킹 규칙을 흐름 단위로 확장할 수 있다.
- 논문 구현은 계획 단계를 분리한 실행기이므로 게이트웨이 단독으로는 전체 적용이 어렵다. 1단계는 출처 태그와 흐름 정책만 도입하고, 계획 분리는 후속 과제로 둔다.

적용 항목은 개발 후보이며 우리 구현이나 배포에서 검증된 기능이 아니다.

## 한계와 사용 조건
